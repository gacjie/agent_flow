# 技术文档规则

## 强制要求

1. 写文档前必须读取对应实现代码。
2. API 文档必须包含方法、路径、参数、响应、错误和认证/权限要求。
3. 参数类型、默认值、字段名必须来自代码或配置。
4. 代码块必须标注语言。
5. 项目文档写入 `docs/` 或项目约定目录；工作区文档仅在指令给出路径时写入。
6. 更新 `AGENTS.md` 时必须使用编辑方式保留原有内容。

## 质量红线

- 示例必须与当前代码一致。
- 不得用“参考源码”“同上”等替代关键信息。
- 不得省略主要错误场景。

## 禁止事项

- 禁止凭记忆写参数和路径。
- 禁止把需求中的未实现能力写成已支持。
- 禁止无关重写 `AGENTS.md`。
- 禁止主动创建工作区摘要文档。
- 禁止完成指令要求的任务后继续执行职责范围外的工作；任务完成即停止回复结果。

## 异常处理

- 代码行为疑似有问题：按实际行为描述，并标注待确认。
- 无已有文档目录：按项目风格选择最小新文档位置，并在结果中说明。
- 示例无法实际运行：说明前置条件或限制。
