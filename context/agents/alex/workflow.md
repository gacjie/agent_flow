# 代码审查工作流

## 工作流介绍

本工作流用于代码审查：接收审查范围指令，执行多维度代码审查并输出报告。非审查类消息不属于本工作流范围。

## [STEP 1/6] 确认范围

读取已加载需求、设计、规范、任务和项目文档。用 `task_lists()` 识别已完成开发任务和重点文件。列出已加载的项目规范文档，确认审查的规范基线。

**完成条件**: 审查范围、重点文件、已加载规范文档和规范基线已明确。
**结束动作**: 调用 work_flow(step="2", summary="...", context_for_next="...")。

## [STEP 2/6] 规划审查方向

列出审查范围、重点文件和关注维度，再开始扫描。关注维度至少覆盖安全、质量、性能、规范符合度、系统运行完整性、生产运行边界、风险触发项、业务逻辑路径、攻击链组合、测试有效性和文档实现一致性；涉及前端时加入入口集成和前端一致性。

**扫描前确认**（全部"是"才继续）：
- [ ] 审查范围已确定（有文件列表或变更范围）？
- [ ] 需求/设计/规范文档已读取？
- [ ] 审查维度和重点文件已列出？
- [ ] 已列出需要追踪的风险触发项、业务逻辑路径、端到端数据流和测试有效性范围？
- [ ] 已列出需要对照的项目文档、业务不变量、生产准入和文档一致性范围？

**完成条件**: 审查方向、维度、重点文件和对照基线已规划完成。
**结束动作**: 调用 work_flow(step="3", summary="...", context_for_next="...")。

## [STEP 3/6] 扫描代码

按以下顺序探索，结合【工具选择】确认无遗漏。

用 `list_files`、`analysis_files`、`read_files`、`search_files` 查看变更范围、同类实现和高风险模式。结合项目安全文档中的审查要点；无项目文档时读取对应安全技能，定位需要完整阅读的入口、数据流和危险调用；只读必要内容，避免无目标全文扫描。

**完成条件**: 变更范围已扫描，高风险模式和需完整阅读的入口已定位。
**结束动作**: 调用 work_flow(step="4", summary="...", context_for_next="...")。

## [STEP 4/6] 多维审查

按项目模式审查。结合【审查标准】确认无遗漏；涉及安全时结合项目安全文档；无项目文档时读取 skills/backend-security.md 和 skills/frontend-security.md 查漏；遇到判断困难时，结合【常见判断】决策。

逐项覆盖：
- 安全：输入源、权限边界、认证会话、敏感信息、注入、XSS/CSRF、配置风险、提示注入和工具越权。
- 风险触发项：按安全底线检查外部输入、身份权限、状态变更、持久化、输出渲染、并发运行、运行暴露和性能资源。
- 业务逻辑：检查所有权、自操作/横向越权、状态禁用、权限变更、敏感操作和拒绝事件审计。
- 权限生命周期：检查客户端高权限字段、授权范围、关键主体保留、状态禁用/撤销后的会话或缓存失效。
- 状态变更：检查方法约束、防伪请求、动态路由/action 白名单、重复提交、事务/锁和冲突处理。
- 攻击链：检查多个低级问题是否可组合成提权、绕过、数据破坏、DoS 或审计缺失。
- 质量：复杂度、重复、错误处理、边界、命名、可维护性。
- 性能：分页、批量查询、查询次数、算法复杂度、资源释放、缓存/连接生命周期、日志/审计增长和并发风险。
- 规范：逐一对照已加载项目规范文档，违反项引用具体文档名和规则条目。
- 文档一致性：对照 API 方法/响应、数据约束、前端变量/响应式规则、后端分层、配置事实和 `[待确认]` 标记是否与实现一致。
- 运行完整性：启动配置、路由注册、菜单/入口、静态资源引用、迁移/配置依赖、生产入口、资源限制、健康检查和核心流程是否接通。
- 前端一致性：涉及页面、模板或静态资源时检查入口集成、样式引用、转义和交互。
- 测试有效性：审查测试是否有真实断言、隔离数据、失败路径、权限边界、输入边界和竞态覆盖。
- Agentic 安全：涉及外部内容、工具输出、MCP 或自动执行链路时检查输出污染、未验证执行、权限边界和审计证据。

**完成条件**: 所有审查维度已逐项覆盖，问题已记录。
**结束动作**: 调用 work_flow(step="5", summary="...", context_for_next="...")。

## [STEP 5/6] 验证与定级

对不确定问题用项目命令、静态检查、搜索或浏览器验证补充证据。结合【严重度分级】按影响和可利用性定级。

**完成条件**: 所有问题已验证并定级，不确定项已补充证据或标记。
**结束动作**: 调用 work_flow(step="6", summary="...", context_for_next="...")。

## [STEP 6/6] 输出

若指令给出路径，写入审查报告。回复必须包含审查范围、问题统计、问题明细、整体结论；无问题时说明剩余风险和未覆盖范围。

**完成条件**: 审查报告已写入或回复已包含完整审查结论。
**结束动作**: 调用 work_flow(step="done", summary="...")。

## 完成检查

自检完成后，结合【禁止事项】确认无违反。

- 是否回溯指令要求，每个审查维度都已覆盖。
- 每个问题是否有路径、行号、标签、严重度。
- 严重或警告问题是否给出修复方向。
- 新增页面或路由是否检查入口集成完整性。
- 是否检查启动配置、路由注册、静态资源引用和核心流程接通风险。
- 是否按安全底线、业务逻辑路径、攻击链组合和端到端数据流完成审查。
- 是否覆盖性能资源、生产运行边界、日志/数据生命周期、缓存/连接失效和资源耗尽风险。
- 是否覆盖权限业务不变量、方法约束、防伪请求、事务/约束、文档实现一致性和生产准入风险。
- 测试代码在范围内时，是否审查测试有效性和覆盖缺口。
- 涉及外部内容、工具输出或自动执行链路时，是否检查提示注入、工具越权、输出污染和敏感信息泄露风险。
- 是否没有修改项目文件或创建修复任务。
- 无问题时是否说明剩余风险和未覆盖范围。

**自检修正**：逐条检查。发现遗漏则分析→补充→重新检查（发现遗漏 → 按遗漏项粒度记录补充次数→回到规划审查方向补充；单个遗漏项连续补充 3 次仍未覆盖 → 标记该项为"放弃"）。持续直到所有项通过或放弃。
