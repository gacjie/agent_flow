# PHP 后端开发工作流

## 1. 读取任务

用 `task_lists` 确认当前 PHP 后端任务。若提供任务 ID，先读取 `task_lists(task_id=..., verbose=true)`，确认 `task_doc`、验收条件和依赖。

## 2. 识别项目范式

扫描项目结构、依赖文件（composer.json）、入口、已有后端模块和测试目录。读取目标文件、同类实现和公共工具，确认框架、错误处理、数据访问和验证方式。任务涉及页面或模板时，还须读取项目基础模板和已有同类页面，确认模板继承结构、可用 block、全局导航和布局模式。

勘察完成后，在回复中列出本次要完成的所有要点、实施顺序，以及需要关注的安全点（输入校验、权限、注入防护等），再开始编码。

## 3. 实施变更

按任务逐项编码：
- 优先复用现有函数、模型、配置和依赖。
- 保持接口契约、字段名、状态值和错误格式一致。
- 覆盖输入、异常、安全、权限、资源释放等边界。

> 防御示例：外部输入 → Request 验证 / FormRequest 校验；SQL → ORM 参数绑定或 PDO 预处理；文件 → `try/finally` 或框架资源管理；异常 → 捕获具体类型，不用裸 `catch(\Exception $e)` 后吞掉。

- 修复任务只处理关联问题文档中的问题。

## 4. 验证

按以下层次逐步验证，每层通过后再进入下一层：

1. **语法检查**：运行 `php -l` 对修改的文件做语法检查，确认无解析错误。
2. **集成启动**：确认本次修改的模块能被项目入口正确加载——运行 `php artisan`（Laravel）、框架启动命令或直接引入入口文件，观察是否报错。
3. **接口可达**：若实现了路由，启动服务后至少请求一个端点确认可响应（非 500 错误）。
4. **测试通过**：运行项目已有测试命令（`php artisan test`、`phpunit`、`./vendor/bin/pest` 等）。

若验证失败，修复后重跑。无法运行时说明具体原因（缺少外部服务、系统依赖等），不得声称"已验证"而未实际执行命令。

## 5. 收尾

更新任务状态。回复中总结：完成了哪些要点、修改文件、验证方式、结果和待确认点。

## 完成检查

- 是否回溯指令要求，逐条确认每个要点都已实现；若有遗漏则补充。
- 是否检查安全规范：输入校验、参数化查询、权限控制、资源释放、敏感信息保护均已覆盖。
- 是否按项目实际识别框架、依赖和测试方式。
- 是否读取目标文件、同类实现和公共工具。
- 是否保持接口契约、字段名、错误格式和权限一致。
- 是否避免裸异常、动态执行和输入拼接风险。
- 是否运行了语法、启动、测试验证。
- 是否更新任务状态并说明无法验证的原因。
- 若任务涉及创建页面或模板，是否确认模板正确继承基础模板、全局布局（header/sidebar/footer/nav）与已有页面一致、引用了项目基础样式和脚本文件。
- 是否检查了以下开发维度（涉及的处理、不涉及的跳过）：日志与可观测性（关键操作是否有日志）、配置外部化（无硬编码魔法值）、向后兼容性（修改已有接口时）。
