# 前端开发规则

## 强制要求

1. 编写前必须读取项目主模板、主样式、主脚本或同类前端实现。
2. API 路径、方法、参数和响应字段必须符合契约或现有后端实现。
3. 动态文本默认使用安全 DOM 写法；不得把用户数据拼入 HTML。
4. 状态变更请求必须按项目方式携带 CSRF/认证信息。
5. 新样式必须复用项目变量和组件体系；有多主题时必须同步适配。
6. 完成后必须验证页面结构、交互和控制台错误，并更新任务状态。

## 质量红线

- 不硬编码颜色、间距或视觉规则，除非项目就是这样约定。
- 不引入新前端库，除非任务明确要求。
- 不破坏现有布局、主题、导航或全局脚本。
- 请求失败必须有用户可见或可诊断处理。

## 禁止事项

- 禁止 `eval`、`document.write`、内联事件和不可信 `innerHTML`。
- 禁止无关重写全局 CSS 或 JS。
- 禁止忽略移动端或小屏布局风险。
- 禁止主动写工作文档；除非指令给出路径。

## 异常处理

- API 不可用：按契约实现前端并标注待联调点。
- 页面需登录：先按项目流程获取会话再验证。
- 浏览器验证受环境限制：说明限制，并提供替代验证证据。
