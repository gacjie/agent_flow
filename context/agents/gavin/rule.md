# Go 后端开发规则

## 强制要求

1. 修改文件前必须读取目标文件和至少一个同类实现。
2. API、数据格式、权限和错误响应必须遵循已加载规范和项目现状。
3. 所有外部输入进入业务逻辑前必须校验。
4. 数据访问必须使用项目安全写法；禁止拼接用户输入。
5. 每个 `error` 返回值必须处理，不得静默忽略。
6. 文件、响应体、事务等资源必须正确释放。
7. 认证和会话相关代码必须遵循安全模式：登录成功后重新生成会话标识；密码或 token 比较使用标准库常量时间函数；跳转目标参数必须校验为站内路径。
8. 登录、注册、密码重置等安全敏感端点必须具备频率限制机制，不得裸露无保护。
9. 完成任务后必须运行可用验证命令，并用 `task_writers` 更新对应任务状态。
10. 创建工具函数前，必须用 search_files 搜索项目中是否已有同名或同功能实现；存在时直接复用。
11. 安全机制（CSRF、认证、输入校验）不得因调试标志或环境变量被条件性跳过；安全代码路径必须无条件执行。
12. 认证错误响应必须统一，不得因账户状态不同（不存在、已禁用、已锁定）返回不同错误信息；防止攻击者枚举有效账户。
13. 登出必须销毁服务端会话数据（非仅清空）；用户删除或禁用必须使该用户所有活跃会话失效。
14. 循环内的数据库操作必须使用事务包裹，不得逐条提交；关联数据加载必须使用 JOIN 或 Preload，禁止循环内逐条查询（N+1）。
15. 实施中优先编写可复用的公共函数/中间件/工具，后编写模块业务逻辑；新建公共代码时确认不与已有实现重复。

## 质量红线

- 不得引入未要求的新依赖、全局可变状态或跨模块副作用。
- 不得硬编码密码、密钥、Token、内部地址等敏感信息。
- 导出标识符按项目风格补充必要注释。
- 验证失败时必须修复或说明阻塞原因。

## 禁止事项

- 禁止未读代码直接写。
- 禁止扩大任务范围做无关重构。
- 禁止吞掉错误或只返回空泛错误。
- 禁止把用户输入直接拼到 SQL、文件路径、命令或模板中。
- 禁止登出接口豁免 CSRF 保护。
- 禁止将用户可控参数未编码拼入重定向 URL。
- 禁止主动写工作文档；除非指令给出路径。
- 禁止完成指令要求的任务后继续执行职责范围外的工作；任务完成即停止回复结果。
- 禁止安全校验函数（密码强度、输入过滤、权限检查）仅在部分入口生效；所有接受对应数据的入口点必须调用。
- 禁止动态 SQL 构造（排序字段、方向、表名）直接使用外部输入；必须校验值在允许列表内。
- 禁止共享可变状态（单例、连接池、全局缓存）在并发环境下无并发保护。
- 禁止框架代码中的会话 Cookie 缺少 HttpOnly 属性；生产环境还须确保 Secure 属性。
- 禁止高频权限/授权检查每次都查库；必须缓存到请求上下文或会话级别。

## 异常处理

- 设计与代码冲突：优先兼容现有代码，并在结果中说明差异。
- 依赖任务未完成：只实现可独立部分，标注待集成点。
- 命令不可运行：报告缺失环境、命令和影响，不伪造通过结果。
