# 后端测试速查

## 【工具选择】

| 目的 | 使用工具 | 使用时机 | 不要用于 |
|------|---------|---------|---------|
| 查看任务要求 | `task_lists` | 确认测试范围、验收标准、任务文档 | 创建或修改任务 |
| 了解项目测试结构 | `list_files` | 找测试目录、配置、脚本、测试资源 | 读取文件内容 |
| 快速定位测试文件 | `search_files` | 搜索 test/spec/e2e/fixture 关键词 | 浏览目录结构 |
| 分析代码逻辑 | `analysis_files` | 理解被测代码结构和调用关系 | 需要完整源码细节时 |
| 读取完整代码 | `read_files` | 需要查看实现、路由、测试样例 | 只需了解文件结构时 |
| 编写测试代码 | `write_files` | 新增或调整测试、fixture、验证脚本 | 修改业务代码 |
| 运行测试 | `run_command` | 执行测试命令、启动服务、采集输出 | 修改文件内容 |

## 【常见判断】

| 遇到情况 | 正确做法 | 错误做法 |
|---------|---------|---------|
| 项目命令不明确 | 按 README/脚本/配置优先，最后才用语言默认命令 | 直接套默认命令 |
| 无法运行测试（缺依赖/环境） | 说明原因，改用可用验证手段并标注阻塞 | 直接报"通过"或报错停止 |
| 需要证明系统能运行 | 先验证构建/启动/最小入口，再测核心接口和数据流 | 只运行单元测试就结束 |
| 测试失败属于既有问题 | 标注"既有缺陷"，与本次变更区分 | 混入本次变更失败项 |
| 接口无文档 | 从代码反推预期行为，标注"推断预期" | 跳过该接口不测 |
| 何时用单元测试 | 纯函数、独立模块、逻辑分支多 | 需要数据库或外部服务的场景 |
| 何时用集成测试 | 模块交互、API 端到端、数据库操作 | 简单工具函数 |
| 何时用端到端接口测试 | 覆盖认证、路由、服务和数据库完整链路时 | 内部纯函数验证 |
| 判断失败归属 | 对比变更范围、调用链和历史测试结果 | 一律归为本次变更 |
| 何时需要 mock | 外部服务不可用、需确定性、慢依赖 | 可用稳定的本地依赖 |
| 测试覆盖边界 | 覆盖变更文件+直接调用方，高风险扩大范围 | 只测变更文件或盲目全量 |

## 输出结构参考

当指令未指定报告格式时，参考以下结构：

```markdown
# 后端测试报告

## 测试范围
模块、接口、服务、数据流、任务 ID。

## 测试环境
运行命令、依赖条件、启动方式、降级说明。

## 测试结果摘要
通过、失败、跳过、阻塞数量。

## 未修复问题索引
| 问题ID | 标签 | 严重度 | 位置 | 根因 | 修复建议 |
|--------|------|--------|------|------|----------|
| T-BE-001 | [Backend] | 严重/警告 | 文件/接口/命令 | ... | ... |

## 失败用例
### T-BE-001 [Backend][严重度] 用例名
- 位置：
- 现象：
- 预期：
- 实际：
- 根因：
- 修复建议：
- 阻塞原因（如有）：

## 通过用例列表

## 未覆盖风险
```
