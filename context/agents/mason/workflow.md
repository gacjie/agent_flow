# 后端开发工作流

## 工作流介绍

本工作流用于后端开发：读取任务指令，实施后端代码编写和验证。非后端开发类消息不属于本工作流范围。

## [STEP 1/6] 读取任务

使用 `task_lists` 定位当前后端开发任务。若给出具体任务 ID，先执行 `task_lists(task_id=..., verbose=true)` 读取完整详情和关联文档。

记录任务标签、阶段父任务 ID、目标文件、验收条件、`task_doc`、修复报告路径和指定问题 ID。修复任务优先处理指令列出的问题，同时修复同技术栈范围内发现的其他明显后端缺陷。

**完成条件**: 任务详情、关联文档、验收条件和修复报告路径已全部读取并记录。
**结束动作**: 调用 work_flow(step="2", summary="任务详情已读取", context_for_next="任务标签/目标文件/验收条件/task_doc")。

## [STEP 2/6] 识别语言、框架和验证入口

按以下顺序探索，结合【工具选择】确认无遗漏：

1. 扫描项目结构和依赖文件，识别本次任务涉及的语言、框架、包管理器和入口。
2. 定位目标文件、同类实现、公共方法和引用方。
3. 确认错误处理、数据访问、输入验证、认证授权、日志和测试方式。
4. 涉及高并发、大数据量、频繁查询或缓存时，read_contexts 读取 `skills/backend-performance.md` 识别适用的性能优化模式。
5. 判断任务虽未明说但后端必须覆盖的适用项：输入校验、权限边界、参数化访问、事务/锁、错误处理、日志和安全默认值。
5. 按安全底线识别外部输入、身份权限、状态变更、持久化、输出渲染、并发运行和运行暴露的适用项；触发则规划实现或报告设计缺口，未触发则不强行实现。
6. 结合【高风险判断】识别安全、性能和运行性触发点：方法约束、防伪请求、高权限字段、授权范围、大小/数量/深度上限、频率限制、时序差异、CRLF/日志注入、环路、唯一性竞态、缓存/连接/日志增长。
7. 涉及第三方 API 或外部服务对接时，识别鉴权失败、超时/取消、限流、重试/幂等、非 JSON 响应、业务错误码和敏感日志过滤。
8. 涉及 SQL、报表、导入导出、批量任务或数据清洗时，识别 NULL、重复数据、分页/批处理、索引/全表扫描、动态字段白名单、事务/回滚和历史数据兼容。
9. 涉及外部内容、模型生成内容、工具输出或自动执行链路时，识别信任边界、权限边界、落地前验证和敏感信息处理。
10. 记录本次修改可用的最小验证入口。
11. 检查 AGENTS.md 服务管理章节：存在则记录命令用于后续验证；不存在则从项目文件中识别启动命令，并用 `write_files` 补充 AGENTS.md 服务管理章节（格式参见已加载的 AGENTS.md 同类章节）。
11. 若任务混入模板结构、HTML、CSS、客户端脚本、页面样式或浏览器交互，只记录交接点，不执行前端实现。
12. 检查是否已加载项目后端安全文档（docs/backend-security.md）：已加载则以项目后端安全文档为准；未加载则 `read_contexts(docs=["skills/backend-security.md"])`。

**完成条件**: 语言、框架、包管理器、最小验证入口、安全文档和所有适用项已识别完毕。
**结束动作**: 调用 work_flow(step="3", summary="语言框架已识别", context_for_next="语言/框架/验证入口/安全触发项")。

## [STEP 3/6] 读取语言技能

根据任务标签和项目事实，结合【语言技能选择】读取一个匹配技能：

- Go → `read_contexts(path="skills/backend-go.md")`
- Python → `read_contexts(path="skills/backend-python.md")`
- PHP → `read_contexts(path="skills/backend-php.md")`
- Node.js → `read_contexts(path="skills/backend-node.md")`
- 其他或无法判断 → `read_contexts(path="skills/backend-generic.md")`

若语言标签与项目文件冲突，以目标文件和任务目标为准，并在总结中说明。

**完成条件**: 已读取与当前任务语言匹配的技能文档。
**结束动作**: 调用 work_flow(step="4", summary="语言技能已读取", context_for_next="技能名称")。

## [STEP 4/6] 规划实施方案

在回复中列出：识别出的语言/框架、已读取技能、要完成的要点、实施顺序、验证命令和安全关注点。

**编码前确认**（全部"是"才开始编码）：
- [ ] 任务详情、任务标签和关联 `task_doc` 已读取？（否 → 先读取）
- [ ] 语言、框架、包管理器和最小验证入口已确认？（否 → 回到步骤 2）
- [ ] 已读取当前语言对应技能？（否 → 回到步骤 3）
- [ ] 至少一个同类实现已找到并确认其模式？（否 → 用 `search_files` 找同类）
- [ ] 本次修改文件范围已确定，且不包含模板结构、样式或客户端交互实现？（否 → 回到步骤 2）
- [ ] 影响面已检查（调用方、类型/接口、测试、配置）？（否 → 搜索引用）
- [ ] 适用的后端默认必需项已识别，且不适用项不会强行实现？（否 → 回到步骤 2）
- [ ] 安全底线已判断，触发项已有实现方案或设计缺口记录？（否 → 回到步骤 2）
- [ ] 安全/性能/运行性触发项已结合【高风险判断】确认，资源上限、生命周期、竞态和注入边界已有处理或缺口记录？（否 → 回到步骤 2）
- [ ] 涉及第三方 API/外部服务时，鉴权失败、超时/取消、限流、重试幂等、非 JSON、业务错误码和敏感日志已有处理方案？（否 → 回到步骤 2）
- [ ] 涉及 SQL/数据处理时，NULL、重复、分页/批处理、索引/全表扫描、动态字段白名单、事务/回滚和历史数据兼容已有处理方案？（否 → 回到步骤 2）
- [ ] 涉及外部内容或工具输出时，落地前校验、权限边界和敏感信息处理已确定？（否 → 回到步骤 2）

**完成条件**: 实施方案已列出，编码前确认清单全部通过。
**结束动作**: 调用 work_flow(step="5", summary="实施方案已规划", context_for_next="要点/文件范围/验证命令")。

## [STEP 5/6] 实施与验证

按问题粒度追踪修复次数。以下 5-A 和 5-B 循环执行，直到所有问题修复或放弃。

### 5-A. 实施变更

按任务类型选择顺序，不涉及的层级跳过：

- 后端服务：公共方法 → 数据层 → 服务/业务层 → 接口/路由层。
- 认证权限：数据/策略 → 服务判断 → 中间件/拦截入口 → 接口接入。
- CLI/脚本：配置 → 核心逻辑 → 命令入口 → 测试。
- 服务端模板数据：后端查询/组装 → 变量注入/绑定 → 保持现有模板结构、HTML、CSS 和客户端脚本不变。

执行要求：
- 按项目模式编码，结合【编码标准】确认无遗漏。
- 遇到判断困难时，结合【常见判断】决策。
- 涉及认证、权限或敏感数据时，结合项目后端安全文档确认覆盖。
- 即使任务未明说，也要落实当前后端变更适用的输入校验、权限边界、参数化访问、事务/锁、错误处理、日志和安全默认值；若设计缺失且无法安全补齐，完成可确定部分并报告设计缺口。
- 涉及外部输入时，确认参数来源隔离、字段白名单、长度/数量限制和错误响应；涉及身份权限时，确认所有权、自操作/横向越权、禁用状态和权限变更失效；涉及持久化或并发时，确认事务、锁、幂等或原子写；涉及运行暴露时，确认资源限制、配置默认值和审计。
- 涉及状态变更入口时，确认方法约束和防伪请求或等价保护；涉及权限授予、高权限字段或关键主体时，确认服务端白名单、授权范围和业务不变量。
- 涉及批量、搜索、树形结构、缓存、连接、日志、会话或临时数据时，确认复杂度、分页/分批、生命周期、清理/轮转、失效和冲突处理。
- 错误分支、认证/权限校验失败、中间件拦截、外部调用返回和状态变更入口必须有调试级别日志（含请求标识、操作路径、失败原因）；有请求追踪设计时确保请求标识在中间件链中传递。
- 涉及第三方 API 或外部服务时，确认鉴权失败、超时/取消、限流、重试幂等、非 JSON 响应、业务错误码映射和敏感日志过滤。
- 涉及 SQL、报表、导入导出、批量任务或数据清洗时，确认 NULL、重复数据、动态字段白名单、分页/批处理、索引/全表扫描、事务回滚和历史数据兼容。
- 涉及生产入口、网络服务或后台任务时，确认超时、连接/线程/进程上限、健康检查、安全传输、安全 Cookie/Token 属性和安全头适用项。
- 外部内容、模型生成内容或工具输出只能在校验来源、格式、权限和敏感信息后落地；自动执行类能力必须保留白名单、权限边界或人工确认。
- 对修复任务，必须先读取 `task_doc` 中指定的问题 ID/章节，优先处理指令列出的问题；同技术栈范围内发现的其他明显后端缺陷也应一并修复。

### 5-B. 验证

按语言技能和项目事实逐层验证，每层通过后再进入下一层：

1. **语法/编译层**：运行当前语言对应的语法检查、编译或导入检查。
2. **集成启动层**：按 AGENTS.md 服务管理章节的命令启动服务（阻塞式命令用 `run_command(background=true)`），确认无初始化错误。验证完毕后用 `run_command(stop_background=PID)` 停止服务。
3. **功能可达层**：对新增或修改的端点、命令或服务端模板数据变量至少验证一次。
4. **风险边界层**：对已触发的方法约束、权限失败、高权限字段拒绝、大小/数量限制、重复提交、冲突错误、清理/失效、第三方 API 失败响应、SQL/数据边界或资源退化路径做最小验证。
5. **测试层**：运行项目测试命令，只修复本次变更引入的失败。

无法运行时说明具体原因和已尝试命令，不得声称"已验证"。

### 5-C. 本轮判断

- 全部通过 → 收尾。
- 有失败 → 逐个问题检查修复次数：未满 3 次的继续修复，满 3 次的标记"放弃"。仍有可修复问题 → 回到 5-A。
- 所有未通过问题均已放弃 → 记录放弃原因和建议后续，收尾。

**完成条件**: 所有验证通过，或所有未通过问题均已修复或标记放弃。
**结束动作**: 全部通过或所有问题已处理 → 调用 work_flow(step="6", summary="实施验证完成", context_for_next="验证结果/放弃项")；有失败且未满 3 次 → 继续本步骤循环修复。

## [STEP 6/6] 收尾

停止验证期间启动的后台服务（`run_command(stop_background=PID)`）。

更新已完成任务状态。回复中总结：识别的语言/框架、读取的技能、完成要点、修改文件（含顺带修复的文件）、实际验证命令和结果、遗留风险、额外发现的问题（跨技术栈发现但未修复的缺陷，含位置和现象描述）。

**完成条件**: 后台服务已停止，任务状态已更新，总结已输出。
**结束动作**: 调用 work_flow(action="done", summary="任务完成")。

## 完成检查

自检完成后，结合【禁止事项】确认无违反。

- 是否回溯指令要求，逐条确认每个要点都已实现。
- 是否识别语言并读取对应语言技能。
- 是否先读后写并复用已有公共方法和模式。
- 涉及安全功能时，是否结合项目后端安全文档确认覆盖。
- 适用的后端默认必需项是否已实现或明确报告设计缺口。
- 安全底线触发的输入、权限、状态、持久化、渲染、并发或运行暴露底线是否已实现或说明不适用/设计缺口。
- 安全/性能/运行性触发项是否结合【高风险判断】检查，资源上限、生命周期、竞态、注入边界和复杂度是否已处理或报告缺口。
- 涉及第三方 API 或外部服务时，是否处理鉴权失败、超时/取消、限流、重试幂等、非 JSON、业务错误码和敏感日志。
- 涉及 SQL、报表、导入导出、批量任务或数据清洗时，是否处理 NULL、重复、分页/批处理、索引/全表扫描、动态字段白名单、事务/回滚和历史数据兼容。
- 涉及外部内容、模型生成内容或工具输出时，是否落实落地前验证、权限边界和敏感信息处理。
- 涉及权限功能时，是否同时实现数据层和拦截中间件。
- 涉及状态变更、高权限字段、授权范围、关键主体、生产入口或后台任务时，是否落实方法约束、防伪请求、服务端白名单、业务不变量、超时和资源边界。
- 是否只修改同技术栈的后端文件（发现的明显后端缺陷可一并修复）。
- 是否在总结中报告了跨技术栈发现但未修复的问题。
- 是否避免模板结构、HTML、CSS、客户端脚本和浏览器交互实现。
- 是否用任务工具更新完成状态并说明结果。
- 若验证未通过，是否说明各轮失败原因和最终状态。

**自检修正**：逐条检查以上清单。发现遗漏则分析原因→规划补充→针对性补充→重新检查。单个检查项连续 3 次补充仍未通过则标记"放弃"并说明原因。持续直到所有项通过或放弃。
