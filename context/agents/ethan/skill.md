# 系统设计速查

## 【工具选择】

| 目的 | 使用工具 | 使用时机 | 不要用于 |
|------|---------|---------|---------|
| 了解项目全貌 | `list_files` | 先确认路径再读文件 | 读取文件内容 |
| 快速了解文件结构 | `analysis_files` | 查看函数/类型列表 | 需要完整源码时 |
| 定位已有模型或接口 | `search_files` | 找到相近实现 | 浏览目录结构 |
| 需要完整实现细节 | `read_files` | 确认需要后再读 | 首次探索（先 analysis） |

## 【常见判断】

| 遇到情况 | 正确做法 | 错误做法 |
|---------|---------|---------|
| 一个 scope 含多个无依赖功能 | 拆为多个 scope | 合并到一个文件 |
| 项目无先例 | 标注"无先例参考"，给出最小方案 | 凭经验不说明 |
| 设计与代码冲突 | 以代码为准，记录差异 | 按设计强改 |
| 摘要文档超 80 行 | 把字段详情移入按需加载文档 | 全放自动加载文档 |
| 不确定字段类型 | 从同类模型推断，标注"参照 XX" | 随意定义 |
| 接口需要分页 | 沿用项目分页格式 | 自创新分页协议 |
| 需要 API/数据库约定 | 由系统设计产出项目实际约定或当前任务契约 | 交给 archer 写契约 |
| Web/API/后台/框架需求 | 判断输入校验、输出编码、CSRF、会话/RBAC、错误、日志、配置是否需基础 scope | 只按用户明说功能设计 |
| 涉及外部内容或工具输出 | 设计信任边界、权限、验证和审计点 | 默认把输出当可信数据 |
| 纯 CLI 或无页面/无用户输入 | 记录 Web 安全项不适用，保留参数校验和运行验证 | 强塞 XSS/CSRF 模块 |
| scope 是目录/应用/包/服务名 | 先按依赖、复用范围和可验收性分类 | 直接当业务模块 |
| scope 承载多个业务能力 | 拆为容器通用 scope + 多个业务模块 scope | 产出一个粗设计文档 |
| 发现通用能力被多个模块依赖 | 独立成基础/平台层或局部通用层设计 | 塞进第一个业务模块 |
| MVC 多应用示例 | 框架底座→多应用容器能力→admin 局部通用→登录/仪表盘/设置等模块 | 把 admin 整体作为模块 |

## 输出结构参考（指令未指定时）

**设计摘要（自动加载层）**：
```
# 系统设计
## Scope Map（scope、层级类型、依赖、下游消费者、是否可独立验收）
## 文件结构（新增/修改文件 + 用途）
## 数据模型（表名、核心字段、关系）
## 模块职责（每模块一句话）
## 接口索引（方法签名或路由列表）
## 设计决策（选型理由、取舍）
```

**模块详细设计（按需加载层）**：
```
# 模块详细设计
## 数据模型（完整字段、类型、约束、索引）
## 接口契约（请求/响应完整字段、状态码、错误格式）
## 模块协作（调用关系、数据流向）
## 边界处理（校验规则、错误场景、并发策略）
```
