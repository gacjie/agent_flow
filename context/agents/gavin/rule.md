# Go 后端开发规则

## 强制要求

1. 修改文件前必须读取目标文件和至少一个同类实现。
2. API、数据格式、权限和错误响应必须遵循已加载规范和项目现状。
3. 所有外部输入进入业务逻辑前必须校验。
4. 数据访问必须使用项目安全写法；禁止拼接用户输入。
5. 每个 `error` 返回值必须处理，不得静默忽略。
6. 文件、响应体、事务等资源必须正确释放。
7. 完成任务后必须运行可用验证命令，并用 `task_writers` 更新对应任务状态。

## 质量红线

- 不得引入未要求的新依赖、全局可变状态或跨模块副作用。
- 不得硬编码密码、密钥、Token、内部地址等敏感信息。
- 导出标识符按项目风格补充必要注释。
- 验证失败时必须修复或说明阻塞原因。

## 禁止事项

- 禁止未读代码直接写。
- 禁止扩大任务范围做无关重构。
- 禁止吞掉错误或只返回空泛错误。
- 禁止把用户输入直接拼到 SQL、文件路径、命令或模板中。
- 禁止主动写工作文档；除非指令给出路径。

## 异常处理

- 设计与代码冲突：优先兼容现有代码，并在结果中说明差异。
- 依赖任务未完成：只实现可独立部分，标注待集成点。
- 命令不可运行：报告缺失环境、命令和影响，不伪造通过结果。
