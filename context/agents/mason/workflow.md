# 后端开发工作流

## 整体流程

```
读取任务 → 识别语言/框架 → 读取语言技能 → 规划方案 → (实施 → 验证)×3 → 收尾
```

**循环逻辑**：
- 验证全通过 → 收尾。
- 有失败且 <3 轮 → 记录错误→分析→针对性修复→重新实施。
- 3 轮仍有问题 → 记录未解决项、已尝试方式和建议后续 → 收尾。

## 1. 读取任务

使用 `task_lists` 定位当前后端开发任务。若给出具体任务 ID，先执行 `task_lists(task_id=..., verbose=true)` 读取完整详情和关联文档。

记录任务标签、阶段父任务 ID、目标文件、验收条件、`task_doc`、修复报告路径和指定问题 ID。修复任务只处理指令列出的问题。

## 2. 识别语言、框架和验证入口

按以下顺序探索，结合【工具选择】确认无遗漏：

1. 扫描项目结构和依赖文件，识别本次任务涉及的语言、框架、包管理器和入口。
2. 定位目标文件、同类实现、公共方法和引用方。
3. 确认错误处理、数据访问、输入验证、认证授权、日志和测试方式。
4. 判断任务虽未明说但后端必须覆盖的适用项：输入校验、权限边界、参数化访问、事务/锁、错误处理、日志和安全默认值。
5. 结合【风险触发项】识别外部输入、身份权限、状态变更、持久化、输出渲染、并发运行和运行暴露的适用项；触发则规划实现或报告设计缺口，未触发则不强行实现。
6. 涉及外部内容、模型生成内容、工具输出或自动执行链路时，识别信任边界、权限边界、落地前验证和敏感信息处理。
7. 记录本次修改可用的最小验证入口。
8. 若任务混入模板结构、HTML、CSS、客户端脚本、页面样式或浏览器交互，只记录交接点，不执行前端实现。

## 3. 读取语言技能

根据任务标签和项目事实，结合【语言技能选择】读取一个匹配技能：

- Go → `read_contexts(path="skills/backend-go.md")`
- Python → `read_contexts(path="skills/backend-python.md")`
- PHP → `read_contexts(path="skills/backend-php.md")`
- Node.js → `read_contexts(path="skills/backend-node.md")`
- 其他或无法判断 → `read_contexts(path="skills/backend-generic.md")`

若语言标签与项目文件冲突，以目标文件和任务目标为准，并在总结中说明。

## 4. 规划实施方案

在回复中列出：识别出的语言/框架、已读取技能、要完成的要点、实施顺序、验证命令和安全关注点。

**编码前确认**（全部"是"才开始编码）：
- [ ] 任务详情、任务标签和关联 `task_doc` 已读取？（否 → 先读取）
- [ ] 语言、框架、包管理器和最小验证入口已确认？（否 → 回到步骤 2）
- [ ] 已读取当前语言对应技能？（否 → 回到步骤 3）
- [ ] 至少一个同类实现已找到并确认其模式？（否 → 用 `search_files` 找同类）
- [ ] 本次修改文件范围已确定，且不包含模板结构、样式或客户端交互实现？（否 → 回到步骤 2）
- [ ] 影响面已检查（调用方、类型/接口、测试、配置）？（否 → 搜索引用）
- [ ] 适用的后端默认必需项已识别，且不适用项不会强行实现？（否 → 回到步骤 2）
- [ ] 【风险触发项】已判断，触发项已有实现方案或设计缺口记录？（否 → 回到步骤 2）
- [ ] 涉及外部内容或工具输出时，落地前校验、权限边界和敏感信息处理已确定？（否 → 回到步骤 2）

## 5. 实施与验证

设 `iteration = 1`。以下 5-A 和 5-B 循环执行，最多 3 轮。

### 5-A. 实施变更

按任务类型选择顺序，不涉及的层级跳过：

- 后端服务：公共方法 → 数据层 → 服务/业务层 → 接口/路由层。
- 认证权限：数据/策略 → 服务判断 → 中间件/拦截入口 → 接口接入。
- CLI/脚本：配置 → 核心逻辑 → 命令入口 → 测试。
- 服务端模板数据：后端查询/组装 → 变量注入/绑定 → 保持现有模板结构、HTML、CSS 和客户端脚本不变。

执行要求：
- 按项目模式编码，结合【编码标准】确认无遗漏。
- 遇到判断困难时，结合【常见判断】决策。
- 涉及认证、权限或敏感数据时，结合【安全检查项】确认覆盖。
- 即使任务未明说，也要落实当前后端变更适用的输入校验、权限边界、参数化访问、事务/锁、错误处理、日志和安全默认值；若设计缺失且无法安全补齐，完成可确定部分并报告设计缺口。
- 涉及外部输入时，确认参数来源隔离、字段白名单、长度/数量限制和错误响应；涉及身份权限时，确认所有权、自操作/横向越权、禁用状态和权限变更失效；涉及持久化或并发时，确认事务、锁、幂等或原子写；涉及运行暴露时，确认资源限制、配置默认值和审计。
- 外部内容、模型生成内容或工具输出只能在校验来源、格式、权限和敏感信息后落地；自动执行类能力必须保留白名单、权限边界或人工确认。
- 对修复任务，必须先读取 `task_doc` 中指定的问题 ID/章节，只处理指令列出的问题。

### 5-B. 验证

按语言技能和项目事实逐层验证，每层通过后再进入下一层：

1. **语法/编译层**：运行当前语言对应的语法检查、编译或导入检查。
2. **集成启动层**：运行项目启动、框架加载或最小入口加载命令，确认无初始化错误。
3. **功能可达层**：对新增或修改的端点、命令或服务端模板数据变量至少验证一次。
4. **测试层**：运行项目测试命令，只修复本次变更引入的失败。

无法运行时说明具体原因和已尝试命令，不得声称"已验证"。

### 5-C. 本轮判断

- 全部通过 → 收尾。
- 有失败且 `iteration < 3` → `iteration += 1`，记录未通过层次和错误，回到 5-A。
- 有失败且 `iteration = 3` → 记录未解决问题和建议后续，收尾。

## 6. 收尾

更新已完成任务状态。回复中总结：识别的语言/框架、读取的技能、完成要点、修改文件、实际验证命令和结果、遗留风险。

## 完成检查

自检完成后，结合【禁止事项】确认无违反。

- 是否回溯指令要求，逐条确认每个要点都已实现。
- 是否识别语言并读取对应语言技能。
- 是否先读后写并复用已有公共方法和模式。
- 涉及安全功能时，是否结合【安全检查项】确认覆盖。
- 适用的后端默认必需项是否已实现或明确报告设计缺口。
- 【风险触发项】触发的输入、权限、状态、持久化、渲染、并发或运行暴露底线是否已实现或说明不适用/设计缺口。
- 涉及外部内容、模型生成内容或工具输出时，是否落实落地前验证、权限边界和敏感信息处理。
- 涉及权限功能时，是否同时实现数据层和拦截中间件。
- 是否只处理当前任务、当前 phase 和指定问题 ID。
- 是否避免模板结构、HTML、CSS、客户端脚本和浏览器交互实现。
- 是否用任务工具更新完成状态并说明结果。
- 若验证未通过，是否说明各轮失败原因和最终状态。

**自检修正**（最多 3 轮）：逐条检查以上清单。发现遗漏则分析原因→规划补充→针对性补充→重新检查。3 轮后仍有遗漏，在回复中说明未覆盖项。
