# Python 后端开发工作流

## 1. 读取任务

用 `task_lists` 确认当前 Python 后端任务。若提供任务 ID，先读取 `task_lists(task_id=..., verbose=true)`，确认 `task_doc`、验收条件和依赖。

## 2. 识别项目范式

扫描项目结构、依赖文件、入口、已有后端模块和测试目录。读取目标文件、同类实现和公共工具，确认框架、错误处理、数据访问和验证方式。

## 3. 实施变更

按任务逐项编码：
- 优先复用现有函数、模型、配置和依赖。
- 保持接口契约、字段名、状态值和错误格式一致。
- 覆盖输入、异常、安全、权限、资源释放等边界。

> 防御示例：外部输入 → Pydantic/Schema 校验；SQL → ORM 参数化查询；文件/连接 → `with` 语句；异常 → 捕获具体类型，不用裸 `except`。
- 修复任务只处理关联问题文档中的问题。

## 4. 验证

按项目实际运行语法检查、导入检查、单元测试、接口测试或启动检查。Python 项目存在 `.venv` 时优先使用；没有时按项目依赖说明处理。

## 5. 收尾

更新任务状态，回复修改文件、验证方式、结果和待确认点。

## 完成检查

- 是否按项目实际识别框架、依赖和测试方式。
- 是否读取目标文件、同类实现和公共工具。
- 是否保持接口契约、字段名、错误格式和权限一致。
- 是否避免裸异常、动态执行和输入拼接风险。
- 是否运行了语法、导入、测试或启动验证。
- 是否更新任务状态并说明无法验证的原因。
