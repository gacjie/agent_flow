# 前端开发规则

> 通用开发经验底线。冲突时以项目规范（docs/）为准。

## 【编码标准】

1. 编写前必须读取任务、关联文档、项目主模板、主样式、主脚本或同类实现。
2. API 路径、方法、参数和响应字段符合契约或现有后端实现；不确定时先搜索验证。
3. 新样式复用项目变量、组件体系和断点规则；多主题项目同步适配各主题。
4. 新增页面引用项目基础样式和脚本；新增 CSS/JS 被对应模板引用。
5. 新增页面集成到应用已有入口结构中（导航、菜单、路由索引等）。
6. 模板中使用的 CSS class 在项目 CSS 中有定义，或本次任务同步创建。
7. 服务端渲染模板的展示层可修改；后端查询、权限逻辑、数据组装和接口流程不得由前端任务新增。
8. 创建 JS 工具函数或组件前，搜索项目已有实现，优先复用现有封装。
9. 不引入新前端库，除非任务明确要求或项目已使用该依赖。
10. 完成后使用 `browser_action` 验证页面结构、交互、控制台和资源加载，并截屏留证。
11. 涉及异步数据、列表、表单、权限或页面入口时，必须处理加载、空数据、错误、权限失败、禁用、焦点、表单边界、可访问性和响应式适用项。
12. 前端变更必须能被用户通过应用入口访问；入口依赖后端缺口时标注交接点，不自行新增后端流程。
13. 外部内容、第三方脚本/资源、用户可控 URL 或工具输出渲染前必须经过转义、白名单或项目安全封装。
14. 必须识别视图层适用风险（异步数据、表单、用户可控内容、权限失败、资源错误）；触发则处理用户可见状态和客户端边界，未触发则不强行实现。无项目前端安全文档时读取 skills/frontend-security.md。
15. 异步请求必须检查 HTTP/业务成功状态、非法响应和超时/取消路径；不得把网络成功等同于业务成功。
16. 交互组件必须处理键盘焦点、ARIA/语义状态、动态选择器转义、事件防抖/节流和主题变量复用的适用项。
17. 涉及异步请求、认证跳转、表单提交或中间件交互时，错误分支必须输出可辨识的控制台错误信息（含请求路径、HTTP 状态码、业务错误描述和响应关键头信息），便于问题定位；不得静默吞掉请求失败、非成功响应或重定向异常。

## 【禁止事项】

- 禁止 `eval`、`document.write`、内联事件和不可信 `innerHTML`。→ 使用 `textContent`、`createElement`、`addEventListener` 和自动转义。
- 禁止无关重写全局 CSS 或 JS。→ 只修改当前任务涉及的样式和脚本。
- 禁止忽略移动端或小屏布局风险。→ 使用项目已有断点和响应式规则适配。
- 禁止覆盖浏览器原生 API（window.confirm/alert/open/fetch 等）。→ 使用独立命名的封装函数。
- 禁止 HTML 转义函数仅转义 `<>&` 而不转义引号。→ 必须覆盖 `< > & ' "`，或使用 DOM API 设置属性值。
- 禁止新增后端查询、权限逻辑、数据组装或接口流程。→ 记录后端交接点，交由 mason 处理。
- 禁止只实现理想成功态。→ 应该：按触发条件补齐加载、空、错误、权限失败、表单边界和响应式状态。
- 禁止把 `fetch` resolved 或 HTTP 200 当作业务成功。→ 应该：检查响应状态、业务状态、非法响应和错误提示。
- 禁止直接渲染外部内容、工具输出或用户可控 URL。→ 应该：先转义、校验来源或使用项目安全封装。
- 禁止把客户端检查当作唯一安全边界。→ 应该：客户端只做体验和早期拦截，后端交接点必须标注。
- 禁止主动写工作文档或修改其他技术栈文件。→ 完成指令要求的前端任务并汇报结果；同技术栈范围内发现的明显前端缺陷可一并修复；跨技术栈（后端代码）发现的问题记入总结的"额外发现"章节。

## 【异常与降级】

| 场景 | 处理 | 禁止 |
|------|------|------|
| 缺失信息导致方向差异 | 完成可确定部分，差异点标注 `[待确认]`，结果中说明假设和阻塞点 | 停止等待外部回复 |
| 用户要求与项目事实冲突 | 说明冲突和影响，按项目事实保守实现 | 为满足指令强改项目基础模式 |
| API 不可用 | 按契约实现前端逻辑，标注待联调点 | 自行设计后端流程 |
| 页面需登录 | 按项目认证流程获取会话并尝试浏览器验证；仍不可用则做模板/结构验证 | 声称已完成真实页面验证 |
| 浏览器验证受限 | 确认原因→尝试解决→降级为语法/结构/资源引用检查→说明局限 | 省略验证说明 |
| 命令不可运行 | 按项目已有命令和依赖状态排查；无法验证则报告具体原因 | 硬编码安装命令或声称已验证 |
| 无法完全满足 | 完成可确定部分，列出已完成/待确认/未完成 | 编造结果或扩大任务范围 |
