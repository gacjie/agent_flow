# 前端开发工作流

## 工作流介绍

本工作流用于前端开发：读取任务指令，实施前端代码编写和验证。非前端开发类消息不属于本工作流范围。

## [STEP 1/5] 读取任务

使用 `task_lists` 确认当前前端任务。若给出任务 ID，先读取 `task_lists(task_id=..., verbose=true)`，确认关联文档、验收条件和依赖接口。

**完成条件**: 任务详情、关联文档、验收条件和依赖接口已全部读取并确认。
**结束动作**: 调用 work_flow(step="2", summary="任务详情已读取", context_for_next="任务要点/验收条件/依赖接口")。

## [STEP 2/5] 识别前端体系

按以下顺序探索，结合【工具选择】确认无遗漏。读取任务相关的模板、样式、脚本、同类页面和关联 task_doc；确认模板继承、样式体系、脚本组织、请求封装、页面入口和服务端已提供的数据变量。涉及长列表/图片密集/动画/首屏加载时，read_contexts 读取 `skills/frontend-performance.md` 识别适用的前端性能优化模式。

检查是否已加载项目前端安全文档（docs/frontend-security.md）：
- 已加载 → 以项目前端安全文档为准
- 未加载 → read_contexts(docs=["skills/frontend-security.md"])

结合项目前端安全文档识别异步数据、表单交互、用户可控内容/URL、权限失败、资源和运行错误的适用项；触发则纳入实施和验证，未触发则不强行实现。

涉及请求封装、列表、搜索、分页、弹窗、折叠、菜单或响应式交互时，额外识别响应状态检查、非法响应、动态选择器转义、键盘焦点、ARIA/语义状态、事件防抖/节流和主题变量复用。

**完成条件**: 模板继承、样式体系、脚本组织、请求封装、安全文档和所有适用项已识别完毕。
**结束动作**: 调用 work_flow(step="3", summary="前端体系已识别", context_for_next="模板/样式/脚本模式/安全触发项")。

## [STEP 3/5] 规划实施方案

在回复中列出本次要完成的所有要点、实施顺序，以及需要关注的安全点、用户可见状态和验证方式。

**编码前确认**（全部"是"才开始编码）：
- [ ] 任务详情和关联 task_doc 已读取？
- [ ] 主模板、主 CSS、主 JS 或同类实现已读取？
- [ ] 至少一个同类页面或组件已确认其模式？
- [ ] 本次修改文件范围已确定？
- [ ] 页面入口、资源引用和验证方式已确定？
- [ ] 服务端渲染页面所需的数据变量已存在或已标注为后端交接点？
- [ ] 加载、空数据、错误、权限失败、表单边界、可访问性和响应式适用项已识别？
- [ ] 安全底线已判断，异步依赖、用户可控 URL、非法响应和客户端边界适用项已纳入方案？
- [ ] 请求成功判定、动态选择器、焦点/ARIA、事件防抖和主题变量适用项已纳入方案？
- [ ] 涉及外部内容、第三方资源、工具输出或用户可控 URL 时，转义、白名单和来源限制已确认？

**完成条件**: 实施方案已列出，编码前确认清单全部通过。
**结束动作**: 调用 work_flow(step="4", summary="实施方案已规划", context_for_next="要点/文件范围/验证页面")。

## [STEP 4/5] 实施与验证

按问题粒度追踪修复次数。以下循环执行，直到所有问题修复或放弃。

### 4-A. 实施变更

按项目模式编码。结合【编码标准】和项目前端安全文档确认无遗漏；遇到判断困难时，结合【常见判断】决策。即使任务未明说，涉及异步数据、表单、权限、列表或页面入口时，也要覆盖加载、空数据、错误、权限失败、禁用、焦点、表单边界、可访问性和响应式适用项。涉及外部内容、第三方资源、工具输出或用户可控 URL 时，必须使用转义、白名单、来源限制或项目安全封装，并标注需要后端兜底的交接点。服务端渲染模板只修改展示结构、样式、客户端脚本和资源引用，不新增后端查询、权限逻辑或数据组装。修复任务必须先读取 `task_doc` 中指定的问题 ID/章节，优先处理指令列出的前端问题；同技术栈范围内发现的其他明显前端缺陷也应一并修复。同一报告中的后端或其他技术栈问题不得顺手修复，应记入总结的"额外发现"章节。

涉及请求代码时必须区分网络成功、HTTP 成功、业务成功和非法响应；涉及动态字段名、动态 selector、用户可控 URL 或列表筛选时必须使用转义、白名单或 DOM API；涉及高频事件时按项目模式加防抖/节流；涉及弹窗、菜单、分页、折叠或表单时必须维护焦点、ARIA/语义状态和键盘可达性。

涉及请求封装、认证跳转或表单提交时，错误分支必须输出可辨识的控制台信息（含请求路径、状态码、响应头关键字段、业务错误描述）；认证失败、CSRF 拒绝、重定向循环和表单提交失败不得静默吞掉——必须在控制台或用户界面输出足够定位问题的上下文。

### 4-B. 验证

使用 `browser_action` 对本次修改/新增的每个页面验证：
1. 启动服务：按 AGENTS.md 服务管理章节的命令启动（阻塞式命令用 `run_command(background=true)`）。
2. 逐一访问页面 URL。
3. 逐项检查：可加载非空白、资源无 404、有样式效果、关键元素可交互、控制台无 JS 错误。
4. 每页截屏留证。
5. 发现问题立即修复后重新验证。

**降级条件**：仅当 browser_action 不可用时（已尝试解决，须说明原因）才降级为模板语法和 HTML 结构验证。
降级处理结合【异常与降级】执行，不得省略验证局限说明。

### 4-C. 本轮结果判断

- 全部通过 → 进入步骤 5。
- 有失败 → 逐个问题检查修复次数：未满 3 次的继续修复，满 3 次的标记"放弃"。仍有可修复问题 → 记录错误并针对性修复。
- 所有未通过问题均已放弃 → 记录放弃原因和已尝试修复，进入步骤 5。

**完成条件**: 所有验证通过，或所有未通过问题均已修复或标记放弃。
**结束动作**: 全部通过或所有问题已处理 → 调用 work_flow(step="5", summary="实施验证完成", context_for_next="验证结果/放弃项")；有失败且未满 3 次 → 继续本步骤循环修复。

## [STEP 5/5] 收尾

停止验证期间启动的后台服务（`run_command(stop_background=PID)`）。

更新任务状态。回复总结：完成要点、修改文件（含顺带修复的文件）、验证页面、验证结果、遗留风险、额外发现的问题（跨技术栈发现但未修复的缺陷，含位置和现象描述）。

**完成条件**: 后台服务已停止，任务状态已更新，总结已输出。
**结束动作**: 调用 work_flow(action="done", summary="任务完成")。

## 完成检查

自检完成后，结合【编码标准】和【禁止事项】确认无遗漏、无违反。

- 是否回溯指令要求，逐条确认每个要点都已实现。
- 是否读过主模板、主 CSS、主 JS 或同类页面。
- 是否遵循 API 契约和字段映射。
- 是否处理加载、成功、失败、空数据和权限失败场景。
- 是否处理表单边界、焦点状态、可访问性和响应式适用项。
- 是否区分网络/HTTP/业务成功，处理非法响应、动态选择器转义、事件防抖和主题变量复用。
- 是否覆盖安全底线中已触发的异步依赖、非法响应、用户可控 URL、权限失败和资源错误。
- 是否使用 `browser_action` 验证并截屏留证。
- 新增页面是否引用所需 CSS/JS；新增 CSS/JS 是否被模板引用。
- 新页面是否集成到应用入口结构中（导航/菜单/路由）。
- 外部内容、第三方资源、工具输出或用户可控 URL 是否已转义、限制来源或使用安全封装。
- 补充提醒（涉及的处理）：可访问性、性能（懒加载/防抖）、浏览器兼容性。
- 若验证未在首轮通过，是否说明了各轮失败原因和最终状态。

**自检修正**：逐条检查以上清单。发现遗漏则分析→补充→重新检查。单个检查项连续 3 次补充仍未通过则标记"放弃"并说明原因。持续直到所有项通过或放弃。
