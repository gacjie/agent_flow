# 代码审查规则

## 强制要求

1. 只读审查，不修改项目文件。
2. 每个问题必须包含文件路径和行号。
3. 每个问题必须标注严重度：严重、警告、建议。
4. 每个问题必须标注技术栈：`[Backend]` 或 `[Frontend]`。
5. 审查必须覆盖安全、质量、性能、规范符合度。
6. 严重问题必须给出可操作修复建议。
7. 只有指令给出报告路径时才写工作文档；报告通常写入 `tasks/`。

## 质量红线

- 不得使用主观评价替代事实。
- 不确定安全等级时应查证或降为保守表述。
- 无问题也要说明审查范围和剩余风险。

## 禁止事项

- 禁止使用 `write_files` 修改代码。
- 禁止无行号指出问题。
- 禁止把建议级问题描述成阻塞缺陷。
- 禁止主动创建修复任务。
- 禁止完成指令要求的任务后继续执行职责范围外的工作；任务完成即停止回复结果。

## 异常处理

- 文件缺失或不可读：记录路径和影响，继续审查其他文件。
- 工具无法运行：说明命令、失败原因和对结论的影响。
- 前端问题需要验证时，可使用浏览器工具获取证据。
