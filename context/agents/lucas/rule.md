# Python 后端开发规则

## 强制要求

1. 修改文件前必须读取目标文件和同类实现。
2. 接口、字段、错误、权限和数据格式必须符合规范和项目现状。
3. 外部输入必须校验；数据库或外部调用必须使用安全参数传递。
4. 异常必须被有意义地处理或向上包装，不得裸 `except` 后吞掉。
5. 文件、连接、游标、临时资源必须释放。
6. 认证和会话相关代码必须遵循安全模式：登录成功后重新生成会话标识；密码或 token 比较使用标准库常量时间函数；跳转目标参数必须校验为站内路径。
7. 登录、注册、密码重置等安全敏感端点必须具备频率限制机制，不得裸露无保护。
8. 完成后必须运行项目适用验证，并用 `task_writers` 更新任务状态。
9. 创建工具函数或通用逻辑前，必须用 search_files 搜索项目中是否已有同名或同功能实现；存在时直接复用。
10. 安全机制（CSRF、认证、输入校验）不得因调试标志或环境变量被条件性跳过；安全代码路径必须无条件执行。
11. 认证错误响应必须统一，不得因账户状态不同（不存在、已禁用、已锁定）返回不同错误信息；防止攻击者枚举有效账户。
12. 登出必须销毁服务端会话数据（非仅清空）；用户删除或禁用必须使该用户所有活跃会话失效。
13. 循环内的数据库操作必须使用事务包裹，不得逐条提交；关联数据加载必须使用 JOIN 或批量查询，禁止循环内逐条查询（N+1）。

## 质量红线

- 不硬编码密钥、密码、Token、环境路径。
- 不引入项目未使用的新框架或大依赖。
- 公共函数按项目风格补充类型提示或 docstring。
- 验证失败不得声明完成。

## 禁止事项

- 禁止未读代码直接写。
- 禁止无关重构。
- 禁止 `eval` / `exec` 处理动态输入。
- 禁止把用户输入直接拼到 SQL、路径、命令或模板。
- 禁止登出接口豁免 CSRF 保护。
- 禁止将用户可控参数未编码拼入重定向 URL。
- 禁止主动写工作文档；除非指令给出路径。
- 禁止完成指令要求的任务后继续执行职责范围外的工作；任务完成即停止回复结果。
- 禁止安全校验函数（密码强度、输入过滤、权限检查）仅在部分入口生效；所有接受对应数据的入口点必须调用。
- 禁止动态 SQL 构造（排序字段、方向、表名）直接使用外部输入；必须校验值在允许列表内。
- 禁止共享可变状态（单例、连接池、全局缓存）在多线程/多协程环境下无并发保护。
- 禁止路径安全校验时忽略操作系统大小写差异；跨平台路径比较必须先规范化再比较。
- 禁止框架代码中的会话 Cookie 缺少 HttpOnly 属性；生产环境还须确保 Secure 属性。
- 禁止高频权限/授权检查每次都查库；必须缓存到请求或会话级别。

## 异常处理

- 未发现虚拟环境或测试脚本：先识别项目推荐方式，再选择最小验证命令。
- 设计与实现冲突：优先兼容现有代码，报告差异。
- 依赖任务缺失：实现可独立部分，标注待集成点。
