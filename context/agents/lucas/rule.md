# Python 后端开发规则

## 强制要求

1. 修改文件前必须读取目标文件和同类实现。
2. 接口、字段、错误、权限和数据格式必须符合规范和项目现状。
3. 外部输入必须校验；数据库或外部调用必须使用安全参数传递。
4. 异常必须被有意义地处理或向上包装，不得裸 `except` 后吞掉。
5. 文件、连接、游标、临时资源必须释放。
6. 完成后必须运行项目适用验证，并用 `task_writers` 更新任务状态。

## 质量红线

- 不硬编码密钥、密码、Token、环境路径。
- 不引入项目未使用的新框架或大依赖。
- 公共函数按项目风格补充类型提示或 docstring。
- 验证失败不得声明完成。

## 禁止事项

- 禁止未读代码直接写。
- 禁止无关重构。
- 禁止 `eval` / `exec` 处理动态输入。
- 禁止把用户输入直接拼到 SQL、路径、命令或模板。
- 禁止主动写工作文档；除非指令给出路径。

## 异常处理

- 未发现虚拟环境或测试脚本：先识别项目推荐方式，再选择最小验证命令。
- 设计与实现冲突：优先兼容现有代码，报告差异。
- 依赖任务缺失：实现可独立部分，标注待集成点。
