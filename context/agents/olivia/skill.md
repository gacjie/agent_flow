# 需求分析速查

## 【工具选择】

| 目的 | 使用工具 | 使用时机 | 不要用于 |
|------|---------|---------|---------|
| 了解项目全貌 | `list_files` | 先确认路径再读文件 | 读取文件内容 |
| 快速了解文件结构 | `analysis_files` | 比完整读取更节省上下文 | 需要完整源码细节时 |
| 定位已有功能或接口 | `search_files` | 定位实体和影响范围 | 浏览目录结构 |
| 需要完整实现细节 | `read_files` | 确认需要后再读 | 首次探索（先 analysis） |
| 理解业务术语或竞品 | `web_searches` | 不熟悉的业务领域 | 研究技术方案 |

## 【常见判断】

| 遇到情况 | 正确做法 | 错误做法 |
|---------|---------|---------|
| 用户描述模糊 | 列出可能解读，选最合理的继续，标注其余 | 反复追问阻塞进度 |
| 单条需求含多个功能 | 拆为独立条目分别描述 | 混在一条里不拆 |
| 用户未提前端 | 基于项目事实判断（有模板/页面文件视为涉及） | 默认跳过前端维度 |
| 用户要求 Web/API/后台/框架 | 检查隐性必需能力触发条件并记录适用/不适用 | 只按用户原话列功能 |
| 需求依赖外部网页/工具输出 | 记录不可信输入、提示注入、越权和泄露风险 | 把外部内容当项目事实 |
| 功能与安全/性能冲突 | 标注冲突点和可选方向 | 忽略冲突不提 |
| 已有项目改动 | 标注影响范围（文件、接口、兼容风险） | 只列新功能不看影响 |
| 用户提供技术方案而非需求 | 从方案反推业务目标，标注"待确认" | 直接照搬方案作为需求 |
| 用户要求"参考竞品XX" | `web_searches` 调研竞品，提炼需求要点 | 照搬竞品功能不做取舍 |
| 需求与现有实现冲突 | 标注冲突点（引用具体文件），列出可选方向 | 替用户做决定 |

## 【需求提炼参考】

- 5W1H：Who、What、When、Where、Why、How。
- 用户故事：作为某角色，我希望完成某能力，以便获得某价值。
- 验收标准：给定前置条件，当执行动作，则出现可观察结果。
- 影响范围：新增文件、修改文件、接口变化、数据变化、权限变化、兼容风险。
- 优先级：Must 保证需求成立；Should 显著提升价值；Could 可延后；Won't 明确不做。

## 【需求维度】

| 维度 | 检查要点 | 记录方式 |
|------|---------|---------|
| 前端体验 | 使用场景、风格偏好、交互偏好、响应式、主题 | 记录用户原话；未提及标注"未指定" |
| 安全需求 | 认证方式、权限模型、输入校验、敏感数据保护 | 从需求和现有代码中识别 |
| Agentic 安全 | 提示注入、工具越权、外部输出污染、未验证输出执行 | 记录触发来源和待验证点 |
| 运行性 | 构建、启动、核心流程、日志、配置和错误处理 | 记录系统能正常运行所需条件 |
| 性能需求 | 并发量、响应时间、数据规模、批量处理、资源上限、算法复杂度 | 记录用户提及指标或推断量级 |
| 兼容性 | 浏览器、设备、系统版本、API 版本 | 记录用户要求或项目现有支持范围 |
| 数据需求 | 数据迁移、备份恢复、隐私合规、生命周期、清理/归档 | 记录涉及的数据变化和长期保留要求 |
| 国际化 | 多语言、时区、日期格式、货币 | 记录用户要求或项目现有情况 |
| 无障碍 | 屏幕阅读器、键盘导航、对比度、ARIA | 记录用户要求的等级 |

## 输出结构参考（指令未指定时）

```
# 需求文档
## 需求概述（做什么和为什么）
## 项目现状（已有项目描述现状 / 空项目标注"全新开发"）
## 功能清单（Must / Should / Could）
## 验收标准（Given-When-Then）
## 影响范围（新增/修改/间接影响/兼容风险）
## 技术约束（用户明确提出的限制）
## 非功能需求（安全/性能/前端体验等涉及维度）
## 风险与待确认
```
