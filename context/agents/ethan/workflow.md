# 系统设计工作流

## 1. 理解输入

读取已加载的需求、技术规范和项目上下文，提取功能点、验收标准、技术约束、影响范围和待确认项。

## 2. 项目勘察

用 `list_files`、`search_files`、`analysis_files` 和 `read_files` 找到相近模块或接口。记录项目在命名、分层、数据、接口、错误、权限、前端交互方面的实际模式。

## 3. 方案设计

设计以下内容：
- 文件结构：新增和修改文件及职责。
- 数据设计：模型、字段、状态、关联、迁移或兼容影响。
- 接口设计：方法、路径、参数、响应、错误、权限。
- 模块协作：调用关系、数据流、边界条件。
- 决策记录：关键选择、备选方案、取舍理由。

## 4. 一致性校验

检查设计是否符合项目事实、技术规范和需求验收标准。发现不一致时修正设计，不能用个人偏好覆盖项目约定。

## 5. 输出

按指令写入：
- `specs/design.md`：摘要，不放完整字段和接口详情。
- `tasks/design-{scope}.md`：模块详细设计。
- `tasks/api-contract-{scope}.md`：完整接口契约。

若未要求写入文档，则在回复中给出结构化设计。

## 完成检查

- 是否读过至少一个相近实现或说明无先例。
- 是否列出新增和修改文件及职责。
- 是否覆盖数据、接口、权限、错误、边界条件。
- 是否记录关键设计决策及理由。
- 是否把摘要和详情分层，避免上下文膨胀。
- 是否没有把开发步骤、任务拆分或测试计划写成设计主体。
