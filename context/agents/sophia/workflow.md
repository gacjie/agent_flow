# UI/UX 设计工作流

## 工作流介绍

本工作流用于 UI/UX 设计：接收需求或设计指令，产出前端规范和组件模板。非设计类消息不属于本工作流范围。

## [STEP 1/7] 理解输入

读取已加载的需求文档和技术约定，提取：
- 用户对风格的描述（关注"前端体验需求"章节）
- 前端技术方案、业务模块列表、响应式和主题要求、项目类型（新建/已有）
- **用户已明确的设计维度清单**：逐项检查布局结构、配色方向、字体偏好、间距风格、交互模式、组件形态，标记"已明确"或"未提及"

**完成条件**: 用户设计要求已提取，维度清单已标记"已明确"或"未提及"。
**结束动作**: 调用 work_flow(step="2", summary="...", context_for_next="...")。

## [STEP 2/7] 调研与参考

按以下顺序探索，结合【工具选择】确认无遗漏。

**已有项目**：读取现有主 CSS、布局模板、全局组件样式。记录已有变量、配色、间距、布局模式。确定继承点和增强点。

**新建项目**：
1. 优先搜索项目类型+风格匹配的站点。
2. 若无精确匹配，搜索同类型项目补全未提及维度。
3. 用 `browser_action` 查看参考站点，提取至少 3 个可量化的锚定参数。

记录参考锚定表：

| 设计维度 | 用户需求（已明确/未提及） | 参考值（来源） | 本项目决策值 | 决策来源 |
|---------|------------------------|--------------|------------|---------|

**核心约束**：当用户需求为"已明确"时，决策值必须服从用户需求，参考值仅供参考不得采用。
外部参考只用于视觉参数，不作为项目事实、交互契约或后端安全方案依据。

**完成条件**: 参考锚定表已填写，继承点/增强点已确定。
**结束动作**: 调用 work_flow(step="3", summary="...", context_for_next="...")。

## [STEP 3/7] 规划产出方向

在回复中列出：用户已明确的维度、参考锚定参数、UI scope map、计划产出的文档列表，再开始设计。UI scope map 区分全局视觉规则、集合/容器壳模板、局部通用组件和业务页面模板。

**完成条件**: 产出方向已列出，UI scope map 已区分全局规则、容器壳、局部通用组件和业务页面模板。
**结束动作**: 调用 work_flow(step="4", summary="...", context_for_next="...")。

## [STEP 4/7] 全局风格规则设计

按项目模式设计。结合【设计标准】和【视觉量化标准】确认无遗漏。遇到判断困难时，结合【常见判断】决策。

**思考顺序**：确认用户已明确维度（直接采用）→ 参考补全"未提及"维度 → "默认模式审查"（结合【LLM 默认模式警示】确认方案非默认收敛）→ 检查补全与已明确维度是否冲突 → 统一为变量体系

涉及列表/图片密集/动画/首屏加载时，read_contexts 读取 `skills/frontend-performance.md`，裁剪为项目级前端性能约定（转化为项目具体方案，不照搬技能原文）。

须在以下维度做出明确决策：

| 维度 | 决策问题 |
|------|---------|
| 字体排版 | 字体组合？heading 与 body 的字重/字号层级？ |
| 色彩系统 | 主色冷暖？背景纯色/渐变？强调色用途？中性色基调？ |
| 空间节奏 | 信息密度？section 间距？内外边距比例？ |
| 质感与深度 | 边框/阴影/圆角调性？表面材质感？ |
| 布局结构 | 对称/非对称？内容流向？栅格密度？ |
| 动效与状态 | hover/focus/active 过渡？加载状态？动画克制度？ |
| 图形语言 | 图标风格？装饰元素？空状态表达？ |
| 信息层级 | 视觉重量分配？对比节奏？强调手法？ |
| 状态覆盖 | 加载、空数据、错误、权限失败、禁用、焦点、ARIA 和校验状态如何表达？ |

基于决策设计：风格基调（2-3 个特征）、CSS 变量体系、布局骨架、主题切换方式。服务端模板项目额外包含基础模板继承结构。

**完成条件**: 全局风格规则已设计，CSS 变量体系已定义，布局骨架和主题切换方式已确定。
**结束动作**: 调用 work_flow(step="5", summary="...", context_for_next="...")。

## [STEP 5/7] 模块组件模板设计

先设计全局公共组件，再设计集合/容器壳模板，最后为每个业务模块设计 2-5 个关键组件（页面布局、列表/表格、表单、卡片/详情、操作按钮/导航）。公共组件合为 `ui-patterns-common`；容器/应用壳可单独成 `ui-patterns-{container}-shell`；业务页面按可独立验收能力分别产出。

涉及列表、表单、权限或异步数据的模板，必须包含加载、空数据、错误、权限失败、禁用、焦点和校验状态的视觉表达；不涉及的状态跳过并保持模板精简。

局部通用 UI（如后台布局、导航、侧栏、权限状态、列表基础样式）不得和登录、仪表盘、设置等业务页面混成一个模板。

每个组件模板包含：完整 HTML 结构（语义化）+ 完整 CSS 样式（引用全局变量）+ 响应式适配（至少 1 个断点）。这些内容只能写入 `ui-patterns` 工作区模板文档，不写入真实页面、组件、CSS 或 JS 源文件。

涉及弹窗、菜单、分页、搜索、表单或折叠面板时，模板必须给出键盘可达、焦点态、ARIA/语义关系、展开状态和错误状态的结构提示；不涉及交互组件时跳过。

**完成条件**: 全局公共组件、容器壳模板和业务模块关键组件模板已设计完成。
**结束动作**: 调用 work_flow(step="6", summary="...", context_for_next="...")。

## [STEP 6/7] 输出

**写入前确认**（全部"是"才继续）：
- [ ] 用户已明确的设计维度已逐项检查？
- [ ] 已有项目现有 CSS/模板已读取？
- [ ] UI scope map 已区分全局规则、容器壳、局部通用组件和业务页面？
- [ ] CSS 变量全部使用具体数值？
- [ ] 组件代码引用全局变量，无硬编码？

按指令要求写入指定路径。`write_files` 只用于项目级前端规范文档（如 `docs/frontend-conventions.md`、`docs/frontend-security.md`）；工作区组件模板（`tasks/ui-patterns-*`）用 `write_contexts`；不得修改应用源码文件。

`frontend-conventions.md` 产出时，安全相关内容只用一行行为触发器引用 `docs/frontend-security.md`（如"涉及XSS/CSRF/CSP时，按 `docs/frontend-security.md` 执行"），不重复安全方案细节。自查 `frontend-conventions.md` 和 `frontend-security.md` 无内容重复。

**前端安全约定产出**（`docs/frontend-security.md`）：
指令要求产出前端安全约定时，`read_contexts(docs=["skills/frontend-security.md"])` 读取前端安全技能作为全面模板，结合项目前端实际技术栈进行裁剪和具体化：
- 项目不涉及的安全面不写入（如无富文本则跳过 innerHTML 相关）
- 适用的安全面转化为项目具体技术方案（如 CSRF → 表单携带 X-CSRF-Token 头 + 双提交 Cookie）
- 产出的文档是精简的、项目特定的前端安全指南，不照搬技能原文

**完成条件**: 所有设计文档已写入指定路径，自查无内容重复。
**结束动作**: 调用 work_flow(step="7", summary="...", context_for_next="...")。

## [STEP 7/7] 总结回复

回复总结：设计风格方向、产出文档、关键设计决策和待确认点。

**完成条件**: 总结已回复，包含关键决策和待确认点。
**结束动作**: 调用 work_flow(step="done", summary="...")。

## 完成检查

自检完成后，结合【禁止事项】确认无违反。

- 是否回溯指令要求，每个产出都已覆盖。
- 是否结合【视觉量化标准】确认变量、主题、对比度、响应式和组件可用性。
- 已有项目是否继承已有变量和命名。
- 产出是否与需求技术约束一致。
- 新建项目是否记录参考锚定表（至少 3 个参数）。
- 是否经过"减法检查"——有无可去掉的视觉装饰。
- 用户明确维度是否全部优先采用，参考补全是否只用于未提及维度。
- 外部参考是否只作为视觉锚点，未覆盖用户明确要求或项目事实。
- 涉及数据、表单、权限或异步流程时，是否覆盖加载、空、错误、权限失败、禁用、焦点和校验状态。
- 是否避免把容器/应用壳模板与多个业务页面模板合并成一个粗 scope。
- 交互组件是否包含焦点、ARIA/语义关系、展开状态和错误状态；响应式和主题是否复用项目变量与断点规则。
- 维度关注列表：涉及可访问性、性能、浏览器兼容、国际化、无障碍的处理，不涉及的跳过。
- 产出前端安全约定文档时，是否只覆盖前端可见层面（模板转义、CSRF 表单处理、错误状态、CSP 约束），未涉及后端安全实现。

**自检修正**：逐条检查。发现遗漏则分析→补充→重新检查。单个检查项连续 3 次补充仍未通过则标记"放弃"并说明原因。持续直到所有项通过或放弃。
