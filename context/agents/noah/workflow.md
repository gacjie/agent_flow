# 任务规划工作流

## 1. 读取输入

- 从自动加载的 `specs/` 中提取需求、技术规范、设计摘要。
- 调用 `list_work_docs(scope="tasks")`，再用 `analysis_work_docs` 快速识别详细设计和接口契约。
- 建立“模块 -> 详情文档 -> 涉及技术栈”的映射。

## 2. 勘察项目

用 `list_files` 确认相关目录和文件是否存在，判断任务是新增、修改还是扩展。文件路径必须按项目实际结构填写。

## 3. 拆分任务

按模块列出文件级变更，拆成叶子任务：
- 标题格式：`[P级][技术栈] 动作对象 — 文件路径`

> 标题示例：
> - `[P0][Backend:Go] 新增用户模型和数据库迁移 — src/model/user.go`
> - `[P1][Frontend] 实现用户列表页和分页交互 — templates/admin/user_list.html`
> - `[P0][Backend:Python] 添加 JWT 认证中间件 — app/middleware/auth.py`
- 描述包含：要做什么、涉及文件、验收条件、依赖或待确认点。
- 任务粒度：一个专家、一个技术栈、一次会话可完成。

## 4. 组织阶段

选择阶段划分方式：
- 全栈项目：后端 -> 前端 -> 测试 -> 文档。
- 模块较独立：按模块阶段，再统一测试和文档。
- 从零项目：基础设施 -> 核心功能 -> 增强 -> 测试文档。

阶段应内聚、可交付、可压缩；每阶段通常 2-5 个叶子任务。

> 阶段划分示例（全栈项目）：
> - Phase-1 后端核心：用户模型迁移、用户 CRUD 接口、认证中间件（3 个叶子）
> - Phase-2 前端页面：登录页、用户列表页、用户表单页（3 个叶子）
> - Phase-3 测试：API 接口测试、登录流程 E2E 测试（2 个叶子）

## 5. 写入与自检

1. 先用 `task_writers` 创建阶段父任务。
2. 记录父任务 ID 后，再用 `task_writers` 创建叶子任务。
3. 为叶子任务设置 `parent_id`、`priority`、必要的 `task_doc` 和依赖信息。
4. 调用 `task_lists()` 自检父子结构、标签、文档关联、任务粒度和覆盖范围。
5. 回复中只总结阶段数量、任务数量、自检结果和待确认点。
