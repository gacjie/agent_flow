# Go 后端开发工作流

## 1. 读取任务

使用 `task_lists` 定位当前 Go 后端任务。若给出具体任务 ID，先执行 `task_lists(task_id=..., verbose=true)` 读取完整详情和关联文档。

## 2. 勘察代码

用 `list_files`、`search_files`、`analysis_files`、`read_files` 找到目标文件、同类实现和公共方法。记录项目在路由、服务、模型、错误、权限、测试上的真实模式。

> 勘察示例：任务要求新增 `POST /api/orders` → 用 `search_files` 找到已有 `POST /api/users` 实现 → 读取其路由注册、参数绑定、服务调用、错误返回 → 按相同模式编写。

勘察完成后，在回复中列出本次要完成的所有要点、实施顺序，以及需要关注的安全点（输入校验、权限、注入防护等），再开始编码。

## 3. 实施变更

按任务粒度逐项修改：
- 优先复用现有函数和类型。
- 保持接口契约、字段名、状态值和错误响应一致。
- 对输入、安全、权限、资源和并发边界做防御处理。

> 防御示例：字符串入参 → 长度和格式校验；DB 查询 → `Where("id = ?", id)` 参数化；文件 → `defer f.Close()`；并发共享状态 → sync.Mutex 或 channel。
- 对修复任务，只处理问题文档覆盖的范围。

## 4. 验证

按以下层次逐步验证，每层通过后再进入下一层：

1. **编译通过**：运行 `go build ./...` 或项目构建命令，确认无编译错误。
2. **集成启动**：运行项目启动命令或 `go run main.go`，确认无 panic 或初始化报错。
3. **接口可达**：若实现了路由，启动服务后至少请求一个端点确认可响应（非 500 错误）。
4. **测试通过**：运行 `go test ./...` 或项目指定测试命令。

若验证失败，修复后重跑。无法运行时说明具体原因，不得声称"已验证"而未实际执行命令。

## 5. 收尾

更新已完成任务状态。回复中总结：完成了哪些要点、修改文件、验证结果、遗留风险。

## 完成检查

- 是否回溯指令要求，逐条确认每个要点都已实现；若有遗漏则补充。
- 是否检查安全规范：输入校验、参数化查询、权限控制、资源释放、敏感信息保护均已覆盖。
- 是否只处理当前任务或当前 phase。
- 是否读过目标文件和同类实现。
- 是否复用已有公共方法和错误处理方式。
- 是否覆盖输入校验、权限、资源释放和敏感信息保护。
- 是否运行了项目可用验证命令。
- 是否用任务工具更新完成状态并说明结果。
- 若任务涉及创建页面或模板，是否确认模板正确引用了项目基础样式和脚本文件。
