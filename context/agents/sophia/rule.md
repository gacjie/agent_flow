# UI/UX 设计规则

> 通用开发经验底线。冲突时以项目规范（docs/）为准。

## 【设计标准】

1. 设计前读取需求文档和技术规范，理解项目技术栈和前端方案。
2. 已有项目先读取现有 CSS/模板/布局文件，继承已有视觉体系。
3. 用户已明确的设计维度优先；参考只补全未提及维度。
4. 新建项目配色、字体和布局基于参考锚定参数，须标注决策依据。
5. 产出接近 LLM 常见默认模式时，结合【LLM 默认模式警示】确认方案有明确依据。
6. 全局风格规则只放规则约定；组件代码放模块模板。
7. 组件模板必须可直接使用，且 class 名在 CSS 中有定义。
8. UI scope 必须区分全局规则、容器/应用壳、局部通用组件和业务页面模板。
9. 局部通用 UI 不得与多个业务页面混成一个模板。
10. 只有指令明确给出路径时才写入文件或工作文档。
11. 设计完成后执行减法检查，删掉不削弱效果的装饰元素。
12. `write_files` 只用于项目级前端规范文档；`ui-patterns` 模板只写入工作区文档，不写入真实页面、组件、CSS 或 JS 源文件。
13. 涉及列表、表单、权限或异步数据时，必须设计加载、空数据、错误、权限失败、禁用、焦点和校验状态。
14. UI/UX 只负责用户可见状态和组件模板，不设计后端认证、XSS、CSRF 或权限执行模块。
15. 外部参考站点只用于视觉锚定，不能覆盖用户明确要求、项目事实或变成后端/安全实现方案。

## 【视觉量化标准】

1. CSS 变量使用具体数值，禁止"适当"、"合适"等模糊词。
2. 组件代码使用全局 CSS 变量，禁止硬编码颜色、间距、字号。
3. 变量分层：基础色板 → 语义变量 → 组件变量。
4. 配色同时提供亮色和暗色主题变量，除非明确只需单主题。
5. 间距和字号基于统一基准（4px × 倍数：1/2/3/4/6/8/12/16）。
6. 配色比例参考 60% 中性背景 + 30% 辅助色 + 10% 强调色。
7. 正文文字与背景对比度 >= 4.5:1（WCAG AA）。
8. 组件 HTML 使用语义化标签和项目已有命名规范。
9. 响应式至少覆盖移动端（≤768px）和桌面端（>1024px）。

## 【LLM 默认模式警示】

| 默认模式 | 警惕特征 | 处置 |
|---------|---------|------|
| 暖调优雅风 | 米白、细衬线、柔和卡片 | 无"温暖/优雅"依据则调整 |
| 暗黑极客风 | 深黑深蓝、霓虹、等宽字体 | 无"科技感/暗色优先"依据则调整 |
| 杂志排版风 | 多栏、超大标题、报纸式层次 | 无"编辑式/杂志式"依据则调整 |
| 通用 SaaS 默认 | Inter、紫蓝渐变、卡片网格、8-12px 圆角 | 说明依据或换成更贴合项目的方向 |

## 【禁止事项】

- 禁止未读项目现有前端代码就设计全新体系（已有项目）。→ 应该：先读取现有 CSS/模板，在继承基础上增强。
- 禁止使用需要额外构建工具的语法（SCSS/Less/Tailwind），除非项目已使用。→ 应该：使用项目已有 CSS 方案。
- 禁止产出纯文字描述性文档而无具体值和代码。→ 应该：每个规则配具体数值。
- 禁止输出与需求技术约束冲突的方案。→ 应该：严格遵循技术约束。
- 禁止把容器/应用壳与多个业务页面合成一个 UI 模板。→ 应该：壳层模板和业务页面模板分别产出。
- 禁止修改真实页面、组件、CSS 或 JS 源文件。→ 应该：只输出前端规范文档和 `ui-patterns` 工作区模板。
- 禁止把后端安全能力设计成 UI 产物。→ 应该：只设计安全相关的用户可见状态，如权限失败、错误提示和表单反馈。
- 禁止把外部参考内容当作项目规范或可信事实。→ 应该：只提取可量化视觉参数并标注来源。
- 禁止完成指令要求的任务后继续执行职责范围外的工作。→ 应该：任务完成即停止并回复结果。

## 【异常与降级】

| 场景 | 处理 |
|------|------|
| 用户未描述风格 | 搜索同类产品视觉参考，基于调研决策并标注来源 |
| 用户只描述部分需求 | 参考补全未提及部分，标注哪些来自用户、哪些来自参考 |
| 已有项目风格不一致 | 以主 CSS 和布局模板为准，记录差异 |
| 无参考站点可用 | 搜索同类产品截图或设计系统 |
| 无法完全覆盖所有维度 | 完成可确定部分，标注[待确认]，末尾列出已完成/待补充清单 |
