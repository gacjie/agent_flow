# 后端开发规则

## 【编码标准】

1. 修改前必须读取任务详情、关联 `task_doc`、目标文件和至少一个同类实现。
2. 必须先识别语言、框架、包管理器、入口和测试方式，再选择验证命令。
3. 必须读取与当前语言匹配的后端技能；无法判断语言时读取 `skills/backend-generic.md`。
4. 外部输入必须校验，数据访问必须参数化或使用项目现有安全封装。
5. 错误响应、状态码、字段命名、分页、事务和日志必须跟随项目事实。
6. 涉及状态一致性时必须使用项目已有事务或锁模式。
7. 涉及认证、授权或敏感数据时，结合项目后端安全文档确认覆盖；无项目文档时读取 skills/backend-security.md。
8. 验证必须使用项目实际命令；无法运行时说明具体原因和已尝试命令。
9. 即使任务未明说，后端变更涉及外部输入、数据访问、状态变更、权限或配置时，也必须落实对应的安全、错误处理、日志（含错误分支的调试级别日志，输出请求标识、操作路径和失败原因，不含密码/Token/PII）和运行验证底线。
10. 设计缺失但存在明显后端安全缺口时，保守实现可确定部分，并在结果中报告设计缺口和未覆盖风险。
11. 外部内容、模型生成内容或工具输出落地前必须校验来源、格式、权限和敏感信息，不得直接执行或持久化未验证结果。
12. 必须识别本次变更的适用安全底线；触发则实现或报告设计缺口，未触发则不强行实现。
13. 涉及资源消耗、批量处理、文件/请求读取、轮询、搜索或树形结构时，必须限制大小/数量/深度/耗时，并避免明显的线性放大或平方级退化。
14. 涉及长期运行状态、日志、审计、会话、缓存或临时数据时，必须有生命周期、清理、轮转、失效或上界控制。
15. 涉及并发安全、CSRF、字段白名单、安全传输或安全头时，按项目后端安全文档处理；无项目文档时读取 skills/backend-security.md。
16. 涉及第三方 API 或外部服务对接时，必须处理鉴权失败、超时/取消、限流、重试/幂等、非 JSON 响应、业务错误码和敏感日志过滤。
17. 涉及 SQL、报表、导入导出、批量任务或数据清洗时，必须处理 NULL、重复数据、分页/批处理、索引/全表扫描、动态字段白名单、事务/回滚和历史数据兼容。

## 【禁止事项】

- 禁止在未识别语言和框架前编码。→ 应该：先扫描配置、入口、同类实现和 docs/ 约定。
- 禁止跳过语言技能读取。→ 应该：按标签或项目事实读取 `skills/backend-{language}.md`。
- 禁止修改模板结构、HTML、CSS、客户端脚本或浏览器交互。→ 应该：说明应交给 emma，自己只处理后端数据查询、组装和变量注入。
- 禁止修复其他技术栈的问题。→ 应该：同技术栈范围内发现的明显后端缺陷均可一并修复；跨技术栈（模板/CSS/客户端脚本）的问题记入总结的"额外发现"章节。
- 禁止修改其他语言或模板/CSS/客户端脚本文件。→ 应该：同技术栈的后端文件中发现的明显缺陷可一并修复；跨技术栈问题记入"额外发现"。
- 禁止声称"已验证"但未执行命令。→ 应该：列出实际执行命令、结果或无法执行原因。
- 禁止引入新框架、新 ORM 或新包管理器。→ 应该：优先使用项目已有依赖和封装。
- 禁止因任务未明说就跳过输入校验、权限边界、参数化访问、事务/锁、错误处理或日志。→ 应该：按变更触发条件落实适用项。
- 禁止按项目形态预设安全实现。→ 应该：只实现当前变更适用的安全底线。
- 禁止擅自扩大设计范围补全整套安全体系。→ 应该：只处理当前任务可确定部分，设计缺口报告给编排师。
- 禁止直接执行或保存外部内容、模型生成代码或工具输出。→ 应该：先校验、限制权限、过滤敏感信息并记录风险。
- 禁止让请求体、文件、日志、缓存、会话、临时数据或审计记录无上界增长。→ 应该：按项目模式设置大小、数量、保留期、清理或轮转策略。
- 禁止只按第三方 API 成功响应实现对接。→ 应该：覆盖鉴权失败、超时/取消、限流、非 JSON、业务错误码、重试幂等和敏感日志过滤。
- 禁止只用小样本或正常数据证明 SQL/数据处理正确。→ 应该：覆盖 NULL、重复、批量、事务回滚、动态字段白名单、历史数据兼容和索引/分页风险。
- 禁止完成指令要求后继续职责范围外工作。→ 应该：任务完成即更新状态并总结。

## 【异常与降级】

| 场景 | 处理 | 禁止 |
|------|------|------|
| 语言标签与项目文件冲突 | 以任务目标和目标文件为准，说明冲突并读取匹配技能 | 强行按标签语言修改无关文件 |
| 找不到语言专属技能 | 读取 `backend-generic.md`，按项目事实执行 | 停止等待或编造技能内容 |
| 依赖未安装或服务无法启动 | 记录缺失依赖、尝试过的命令和可验证部分 | 声称完整启动验证通过 |
| 设计与代码事实冲突 | 兼容现有代码，说明偏离设计的原因 | 按设计强改现有稳定模式 |
| 任务混入前端实现 | 只完成后端数据与变量注入部分，标注前端交接点 | 顺手改模板结构、页面样式或交互 |
| 无法完全满足 | 输出已完成、待确认、无法完成三段式总结 | 声称全部完成 |
