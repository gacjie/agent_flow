# UI/UX 设计工作流

## 1. 理解输入

读取已加载的需求文档（specs/requirement.md）和技术规范（specs/tech-spec.md），提取：
- 用户对风格的描述或暗示（关注"前端体验需求"章节）
- 前端技术方案（原生 HTML/CSS、Vue、React、模板引擎等）
- 功能模块列表（决定需要产出多少个 scope 的组件模板）
- 响应式和主题要求
- 项目类型（新建/已有）
- **用户已明确的设计维度清单**：逐项检查用户是否明确了以下维度——布局结构、配色方向、字体偏好、间距风格、交互模式、组件形态。标记为"已明确"或"未提及"。后续步骤中，"已明确"的维度只能从用户需求获取，"未提及"的维度由参考补全。

## 2. 调研与参考

根据项目状态进行调研：

**已有项目**：
- 用 `list_files`、`read_files` 读取现有主 CSS 文件、布局模板、全局组件样式。
- 记录已有 CSS 变量、配色方案、间距习惯、布局模式。
- 确定继承点和增强点。

**新建项目**：

> ⚠️ 参考的作用是**补全用户需求未覆盖的空白**。用户已明确要求的维度（步骤 1 中标记为"已明确"的），禁止被参考站点覆盖。

搜索策略（按优先级尝试）：
1. **优先搜索项目类型+风格都匹配的站点**（如用户要"极简风管理后台"→搜"minimalist admin dashboard design"）
2. **若无精确匹配，搜索同类型项目**（同项目类型，不限风格）——用于补全用户未提及的设计维度（如布局、组件模式）
3. 搜索到的参考站点用 `browser_action` 查看，提取可量化的视觉参数

从参考中提炼至少 3 个可量化的"锚定参数"（如：主色相值、圆角尺寸、字体选择、阴影深度、间距基准、布局模式、留白节奏）。

记录参考锚定表：
| 设计维度 | 用户需求（已明确/未提及） | 参考值（来源） | 本项目决策值 | 决策来源 |
|---------|------------------------|--------------|------------|---------|

**填写规则**：
- "用户需求"列：从步骤 1 的维度清单中获取，标注"已明确：xxx"或"未提及"
- "决策来源"列：写明该决策来自用户需求还是参考补全
- **核心约束**：当"用户需求"为"已明确"时，"本项目决策值"必须服从用户需求，参考值仅供参考不得采用

## 3. 全局风格规则设计

须在以下维度做出明确决策（具体方向由调研参考决定，不得留空或沿用未经思考的默认值）：

> 以下决策须遵守步骤 1 的维度清单：用户已明确的维度直接采用用户要求，只有"未提及"的维度才需要设计决策。

| 维度 | 决策问题 |
|------|---------|
| 字体排版 | 什么字体组合？heading 与 body 的字重/字号层级差如何体现？ |
| 色彩系统 | 主色冷暖倾向？背景纯色/渐变/纹理？强调色用于何处？中性色基调？ |
| 空间节奏 | 信息密度偏紧凑还是留白？section 间距节奏？内外边距比例？ |
| 质感与深度 | 边框/阴影/圆角的整体调性（硬朗/柔和/无修饰）？表面材质感？ |
| 布局结构 | 对称/非对称？内容流向？栅格密度？视觉重心位置？ |
| 动效与状态 | hover/focus/active 过渡方式？加载状态？动画克制度（无/轻微/丰富）？ |
| 图形语言 | 图标风格（线性/面性/双色）？装饰元素？空状态视觉表达？ |
| 信息层级 | 视觉重量如何分配？对比节奏？用什么手法强调重点（大小/颜色/位置）？ |

基于以上决策，设计以下内容（均须使用具体数值）：
- **风格基调**：用 2-3 个具体特征描述（如"大圆角 12px、轻阴影、高留白"）。
- **CSS 变量体系**：基础色板、语义变量（亮/暗两套）、间距基准和倍数、字号层级、圆角和阴影。
- **布局骨架**：页面整体结构（侧边栏/顶栏/内容区的 Grid/Flex 方案）。
- **主题切换方式**：data-theme 属性切换或 prefers-color-scheme。
- 服务端模板项目额外包含：基础模板继承结构、全局布局骨架、新页面接入方式。

## 4. 模块组件模板设计

为每个功能模块设计 2-5 个关键组件的具体代码：
- 页面布局（该模块的内容区结构）
- 列表/表格组件
- 表单组件
- 卡片/详情组件
- 操作按钮/导航组件

公共布局和通用组件（导航、侧边栏、页脚、toast、modal）合为 `ui-patterns-common`。

每个组件包含：
- 完整 HTML 结构（语义化标签）
- 完整 CSS 样式（使用全局变量）
- 响应式适配代码（至少 1 个断点）

## 5. 输出

按指令写入指定产物：
- `specs/ui-patterns.md`：全局风格规则（纯规则约定，不含组件代码）。
- `tasks/ui-patterns-{scope}.md`：模块组件代码模板。scope 与 design 模块拆分对齐。
- `tasks/ui-patterns-common.md`：公共布局和通用组件代码。

## 完成检查

- 是否回溯指令要求，逐条确认每个要求的产出都已覆盖；若有遗漏则补充。
- CSS 变量是否全部使用具体值（无模糊描述）。
- 组件代码是否全部引用全局变量（无硬编码颜色/间距）。
- 亮色和暗色主题变量是否都有定义。
- 间距是否基于统一基准且倍数关系清晰。
- 配色对比度是否满足 WCAG AA（>= 4.5:1）。
- 组件代码是否可直接使用（非伪代码）。
- 响应式断点是否至少覆盖移动端和桌面端。
- 已有项目时是否继承了项目已有变量和命名。
- 产出是否与需求文档技术约束一致（不引入需求未允许的工具/框架）。
- 新建项目时，是否记录了参考锚定表（至少 3 个来自真实参考站点的具体参数）？
- 配色、字体、布局三个维度中，是否至少有 2 个维度做出了有依据的主动决策，而非沿用 LLM 未经引导时的统计默认（如 Inter + 紫蓝渐变 + 等宽卡片网格）？若项目风格确实需要接近默认方案，须标注理由。
- 步骤 1 中标记为"已明确"的维度，产出是否忠实遵循了用户需求？若发现任何"已明确"维度的决策来自参考站点而非用户需求，须修正。
- 参考锚定表的"决策来源"列是否填写完整？是否有"已明确"维度错误地标注为参考来源？

## 6. 总结回复

回复中总结：设计了什么风格方向、产出了什么文档、关键设计决策和待确认点。
