# 项目类型识别与裁剪

> 根据项目特征识别类型，按类型差异裁剪安全和性能关注面。设计阶段读取本技能后，跳过不适用的安全/性能面，聚焦项目真正需要的防护和优化。

## 一、项目类型识别表

| 项目类型 | 识别线索 | 典型架构 |
|---------|---------|---------|
| Web 管理后台(SSR) | 模板引擎、session 认证、后台菜单、CRUD 表格、角色权限 | MVC + 模板渲染 |
| RESTful API 服务 | JSON 响应、Token 认证、无模板、第三方消费 | 路由 + 中间件 + Handler |
| SPA + API 分离 | 前端框架(React/Vue) + 独立 API 后端 | 前端 SPA + 后端 API |
| CLI 工具 | 命令行参数、无 HTTP、脚本形式、管道输入输出 | 命令解析 + 执行 |
| 微服务 | 多服务通信、gRPC、消息队列、服务发现 | 分布式 + 网关 |
| 开放平台 | OAuth、开发者文档、Webhook、SDK、第三方集成 | 网关 + 限流 + 版本化 |
| 移动端后端 | 移动端特有认证、推送通知、设备管理 | API + 推送 + 存储 |

### 识别方法

检查项目的路由定义、模板文件、认证方式、响应格式等线索。多数项目属于一种主类型或两种混合（如 Web 后台 + API）。混合类型取各类型关注面的**并集**。

## 二、各类型安全重点差异

### Web 管理后台（SSR/模板渲染）

| 安全面 | 级别 | 说明 |
|--------|------|------|
| CSRF | ★★★必须 | 表单 + AJAX 均需 token 保护 |
| XSS | ★★★必须 | 模板自动转义 + 富文本白名单过滤 |
| Session 管理 | ★★★必须 | HttpOnly + Secure + SameSite 三件套 |
| RBAC 权限矩阵 | ★★★必须 | 每个接口 + 每个资源验证所有权 |
| 点击劫持 | ★★☆重要 | X-Frame-Options: DENY |
| 安全头 | ★★☆重要 | CSP / HSTS / X-Content-Type-Options |
| Cookie 安全 | ★★★必须 | `__Host-` 前缀防子域伪造 |

### RESTful API 服务

| 安全面 | 级别 | 说明 |
|--------|------|------|
| BOLA(越权) | ★★★必须 | API 最常见漏洞——修改 ID 即越权 |
| 认证 Token | ★★★必须 | OAuth2.0+PKCE / JWT 签名验证 / 短有效期+轮换 |
| 速率限制 | ★★★必须 | 按用户/Key 限制（非仅 IP），认证端点更严 |
| Schema 验证 | ★★★必须 | 请求体 JSON Schema 验证 |
| 数据暴露 | ★★☆重要 | 响应最小数据原则，密码字段 `json:"-"` |
| CSRF | ☆☆☆不适用 | 纯 API 无浏览器 Cookie 场景不需要 |
| CORS | ★★☆重要 | 明确指定允许源，不用通配符 |

### 微服务架构

| 安全面 | 级别 | 说明 |
|--------|------|------|
| East-West 加密 | ★★★必须 | 服务间 mTLS，"内部安全"是虚假假设 |
| Zero Trust | ★★★必须 | 每个微服务独立验证调用者身份 |
| 服务间认证 | ★★★必须 | SPIFFE 证书 / Service Mesh 自动加密 |
| API 网关 | ★★★必须 | North-South 统一入口（认证/限流/日志） |
| 证书管理 | ★★☆重要 | 自动签发 / 轮换 / 吊销 |

### CLI 工具

| 安全面 | 级别 | 说明 |
|--------|------|------|
| 命令注入 | ★★★必须 | 参数白名单验证，避免 shell=true |
| 文件路径验证 | ★★★必须 | 防路径穿越，限制工作目录 |
| 环境变量泄露 | ★★☆重要 | 不在日志/输出中暴露密钥 |
| 临时文件竞争 | ★★☆重要 | 安全创建临时文件，权限最小化 |
| CSRF/XSS/Session | ☆☆☆不适用 | 无 HTTP 无浏览器 |

## 三、各类型性能重点差异

| 项目类型 | 核心性能关注 | 不适用 |
|---------|------------|--------|
| Web 后台(SSR) | 页面渲染(LCP/CLS)、数据库查询、静态资源缓存、模板缓存 | 高并发 API 限流 |
| API 服务 | 响应延迟<200ms、连接池、限流/熔断、序列化效率、分页 | 首屏渲染、CSS 优化 |
| SPA + API | 前端(CWV/代码分割/懒加载) + 后端(API 响应) | 模板渲染 |
| CLI | 启动速度、单次执行效率、内存占用、避免大量初始化 | 并发/连接池/缓存 |
| 微服务 | 服务间延迟、Sidecar 开销、服务发现效率、级联超时 | 单体内存管理 |
| 开放平台 | 限流精度、Token 验证效率、Webhook 投递可靠性 | 内部微服务通信 |

## 四、设计裁剪决策表

供设计阶段根据项目类型判断各安全/性能面的处理方式：

| 安全/性能面 | Web 后台 | API 服务 | CLI | 微服务 | SPA+API |
|------------|---------|---------|-----|--------|---------|
| CSRF 保护 | 必须 | 不适用 | 不适用 | 不适用 | 按场景 |
| XSS 防护 | 必须 | 不适用 | 不适用 | 不适用 | 前端必须 |
| Session 管理 | 必须 | 不适用 | 不适用 | 不适用 | 前端管理 |
| Token 认证 | 可选 | 必须 | 不适用 | 必须 | 必须 |
| 速率限制 | 重要 | 必须 | 不适用 | 必须 | 必须 |
| mTLS/服务间认证 | 不适用 | 不适用 | 不适用 | 必须 | 不适用 |
| 前端 CWV | 必须 | 不适用 | 不适用 | 不适用 | 必须 |
| 数据库优化 | 必须 | 必须 | 按场景 | 必须 | 必须 |
| 连接池 | 必须 | 必须 | 不适用 | 必须 | 后端必须 |
| 虚拟滚动 | 按需 | 不适用 | 不适用 | 不适用 | 按需 |

**使用方法**："不适用"的面直接跳过不写入项目文档；"必须"的面必须产出具体方案；"按场景"/"按需"的面根据项目实际需求判断。

## 五、WAF 与 API 安全差异提示

- WAF 对 Web 应用有效（模式匹配拦截注入/XSS），但对 API 不足——API 攻击利用**业务逻辑缺陷**，请求协议层合法
- Web 关注 North-South 流量（外部→内部），微服务关注 East-West 流量（服务→服务）
- API 攻击面远大于 Web：每个客户端都是入口（移动/IoT/第三方）
- 统一安全策略是必须的——分离 Web 安全与 API 安全会创造危险间隙

## 六、生产就绪原则

**核心规则**：所有设计和开发必须以生产环境为目标，禁止引入仅适用于开发/测试场景的服务、包或依赖。

| 禁止使用 | 生产替代 |
|---------|---------|
| Python `http.server` | Gunicorn/uWSGI + Nginx |
| Node `json-server` / `live-server` | Express/Fastify + 真实数据库 |
| PHP 内置服务器 `php -S` | Apache/Nginx + PHP-FPM |
| Go `net/http` 直接暴露 | 反向代理(Nginx/Caddy) + 超时配置 |
| SQLite 作为多用户 Web 后端 | PostgreSQL / MySQL |
| `nodemon`/`air` 写入 Dockerfile | 生产构建 + 进程管理器(PM2/systemd) |
| `DEBUG=True` / 开发模式 flag | 生产配置分离，环境变量控制 |

**设计阶段检查**：技术选型时确认所选依赖适用于生产部署。开发工具只允许出现在 devDependencies 或开发脚本中，不得进入运行时依赖。
