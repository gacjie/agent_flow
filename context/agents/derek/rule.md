# 通用全栈开发规则

## 强制要求

1. 修改文件前必须读取目标文件和同类实现。
2. 接口、字段、错误、权限和数据格式必须符合规范和项目现状。
3. 外部输入必须校验；数据库操作必须使用参数化查询或 ORM 绑定，禁止字符串拼接用户输入。
4. 异常必须被有意义地处理，不得静默忽略或吞掉错误。
5. 文件、连接、流等资源必须正确释放。
6. 认证和会话相关代码必须遵循安全模式：登录成功后重新生成会话标识；密码比较使用常量时间函数；跳转目标参数必须校验为站内路径。
7. 安全敏感端点必须具备频率限制机制。
8. 完成后必须运行项目适用验证，并用 `task_writers` 更新任务状态。
9. 创建工具函数前，必须用 search_files 搜索项目中是否已有同功能实现；存在时直接复用。
10. 安全机制不得因调试标志或环境变量被条件性跳过。
11. 认证错误响应必须统一，防止攻击者枚举有效账户。
12. 登出必须销毁服务端会话数据；用户禁用必须使所有活跃会话失效。
13. 循环内的数据库操作必须使用事务；关联数据必须使用 JOIN 或预加载，禁止 N+1 查询。
14. 实施中优先编写可复用的公共函数/中间件/工具，后编写模块业务逻辑；新建公共代码时确认不与已有实现重复。

## 质量红线

- 不硬编码密钥、密码、Token、环境路径。
- 不引入项目未使用的新框架或大依赖。
- 公共函数按项目风格补充文档注释或类型声明。
- 验证失败不得声称完成。

## 禁止事项

- 禁止未读代码直接写。
- 禁止无关重构。
- 禁止任何形式的动态代码执行处理用户输入（eval、exec、反射调用等）。
- 禁止把用户输入直接拼到 SQL、路径、命令或模板。
- 禁止登出接口豁免 CSRF 保护。
- 禁止将用户可控参数未编码拼入重定向 URL。
- 禁止主动写工作文档；除非指令给出路径。
- 禁止完成指令要求的任务后继续执行职责范围外的工作；任务完成即停止回复结果。
- 禁止安全校验函数仅在部分入口生效。
- 禁止动态 SQL 构造直接使用外部输入；必须校验值在允许列表内。
- 禁止共享可变状态在并发环境下无保护。
- 禁止会话 Cookie 缺少 HttpOnly 属性。

## 异常处理

- 项目语言或框架不熟悉：先通过文件结构和配置识别，参考同类文件模式实现。
- 设计与实现冲突：优先兼容现有代码，报告差异。
- 依赖任务缺失：实现可独立部分，标注待集成点。
