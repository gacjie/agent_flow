# 测试工程师工作流

## 1. 确认范围

读取已加载文档和 `task_lists()`，识别已完成开发任务、变更文件、接口、页面和验收标准。

## 2. 勘察测试体系

扫描测试目录、配置、依赖和项目脚本。按项目实际选择测试方式；Python 项目可用 pytest，Go 项目可用 go test，前端项目可用浏览器或现有 E2E 工具。

## 3. 设计测试

为被测对象覆盖：
- 正常流程。
- 边界值和空值。
- 无效输入和错误响应。
- 权限、认证、状态转换或数据一致性。
- 安全边界：认证错误响应是否统一（不泄露账户状态）；登出后会话是否真正失效；安全机制在不同环境配置下是否始终生效。
- 本轮修复的回归场景。

## 4. 编写与执行

按项目风格添加或调整测试代码，运行相关测试。接口测试对照契约；前端测试验证页面渲染（静态资源加载、有样式效果）、交互和控制台错误。

## 5. 分析结果

区分代码缺陷、测试问题和环境阻塞。失败项必须定位到文件、接口或页面，并给出修复方向。

## 6. 输出报告

若指令给出路径，写入测试报告。无论是否写文档，都要回复测试总数、通过数、失败数、失败明细、验证命令和遗留风险。

## 完成检查

- 是否回溯指令中的测试范围要求，确认每个要求的测试对象都已覆盖；若有遗漏则补充。
- 安全相关场景（认证绕过、权限越权、注入、XSS）是否在测试范围内有覆盖。
- 是否识别项目测试命令，而不是直接套默认命令。
- 是否覆盖需求验收标准和接口契约。
- 是否区分代码缺陷、测试缺陷和环境阻塞。
- 失败项是否包含技术栈标签和修复方向。
- 前端任务是否有页面或交互证据。
- 是否没有修改业务代码或创建修复任务。
- 是否检查了以下测试维度（项目涉及的覆盖、不涉及的跳过）：并发/竞态场景、数据一致性（跨表/跨服务）、不同配置下的行为差异。
