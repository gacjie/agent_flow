# 前端开发工作流

## 整体流程

```
读取任务(1) → 识别前端体系(2) → 规划方案(3) → (实施→验证)×3(4) → 收尾(5)
```

## 1. 读取任务

使用 `task_lists` 确认当前前端任务。若给出任务 ID，先读取 `task_lists(task_id=..., verbose=true)`，确认关联文档、验收条件和依赖接口。

## 2. 识别前端体系

按以下顺序探索，结合【工具选择】确认无遗漏。读取任务相关的模板、样式、脚本、同类页面和关联 task_doc；确认模板继承、样式体系、脚本组织、请求封装、页面入口和服务端已提供的数据变量。

结合【风险触发项】识别异步数据、表单交互、用户可控内容/URL、权限失败、资源和运行错误的适用项；触发则纳入实施和验证，未触发则不强行实现。

## 3. 规划实施方案

在回复中列出本次要完成的所有要点、实施顺序，以及需要关注的安全点、用户可见状态和验证方式。

**编码前确认**（全部"是"才开始编码）：
- [ ] 任务详情和关联 task_doc 已读取？
- [ ] 主模板、主 CSS、主 JS 或同类实现已读取？
- [ ] 至少一个同类页面或组件已确认其模式？
- [ ] 本次修改文件范围已确定？
- [ ] 页面入口、资源引用和验证方式已确定？
- [ ] 服务端渲染页面所需的数据变量已存在或已标注为后端交接点？
- [ ] 加载、空数据、错误、权限失败、表单边界、可访问性和响应式适用项已识别？
- [ ] 【风险触发项】已判断，异步依赖、用户可控 URL、非法响应和客户端边界适用项已纳入方案？
- [ ] 涉及外部内容、第三方资源、工具输出或用户可控 URL 时，转义、白名单和来源限制已确认？

## 4. 实施与验证

设 iteration = 1，以下循环最多 3 轮。

### 4-A. 实施变更

按项目模式编码。结合【编码标准】、【前端安全检查项】和【风险触发项】确认无遗漏；遇到判断困难时，结合【常见判断】决策。即使任务未明说，涉及异步数据、表单、权限、列表或页面入口时，也要覆盖加载、空数据、错误、权限失败、禁用、焦点、表单边界、可访问性和响应式适用项。涉及外部内容、第三方资源、工具输出或用户可控 URL 时，必须使用转义、白名单、来源限制或项目安全封装，并标注需要后端兜底的交接点。服务端渲染模板只修改展示结构、样式、客户端脚本和资源引用，不新增后端查询、权限逻辑或数据组装。修复任务必须先读取 `task_doc` 中指定的问题 ID/章节，只处理指令列出的前端问题；同一报告中的后端或其他技术栈问题不得顺手修复。

### 4-B. 验证

使用 `browser_action` 对本次修改/新增的每个页面验证：
1. 启动服务（`run_command`）。
2. 逐一访问页面 URL。
3. 逐项检查：可加载非空白、资源无 404、有样式效果、关键元素可交互、控制台无 JS 错误。
4. 每页截屏留证。
5. 发现问题立即修复后重新验证。

**降级条件**：仅当 browser_action 不可用时（已尝试解决，须说明原因）才降级为模板语法和 HTML 结构验证。
降级处理结合【异常与降级】执行，不得省略验证局限说明。

### 4-C. 本轮结果判断

- 全部通过 → 进入步骤 5。
- 有失败且 iteration < 3 → iteration += 1，记录错误并针对性修复。
- 有失败且 iteration = 3 → 记录未解决问题和已尝试修复，进入步骤 5。

## 5. 收尾

更新任务状态。回复总结：完成要点、修改文件、验证页面、验证结果和遗留风险。

## 完成检查

自检完成后，结合【编码标准】、【前端安全检查项】和【禁止事项】确认无遗漏、无违反。

- 是否回溯指令要求，逐条确认每个要点都已实现。
- 是否读过主模板、主 CSS、主 JS 或同类页面。
- 是否遵循 API 契约和字段映射。
- 是否处理加载、成功、失败、空数据和权限失败场景。
- 是否处理表单边界、焦点状态、可访问性和响应式适用项。
- 是否覆盖【风险触发项】中已触发的异步依赖、非法响应、用户可控 URL、权限失败和资源错误。
- 是否使用 `browser_action` 验证并截屏留证。
- 新增页面是否引用所需 CSS/JS；新增 CSS/JS 是否被模板引用。
- 新页面是否集成到应用入口结构中（导航/菜单/路由）。
- 外部内容、第三方资源、工具输出或用户可控 URL 是否已转义、限制来源或使用安全封装。
- 补充提醒（涉及的处理）：可访问性、性能（懒加载/防抖）、浏览器兼容性。
- 若验证未在首轮通过，是否说明了各轮失败原因和最终状态。

**自检修正**（最多 3 轮）：逐条检查以上清单。发现遗漏则分析→补充→重新检查。3 轮后仍有遗漏，在回复中说明。
