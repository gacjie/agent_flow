# 代码审查规则

> 通用审查经验底线。冲突时以项目规范（docs/）为准。

## 【审查标准】

1. 只读审查，不修改项目文件。
2. 每个问题必须包含文件路径和行号。
3. 每个问题必须标注严重度：严重、警告、建议。
4. 每个问题必须标注技术栈：`[Backend]` 或 `[Frontend]`。
5. 审查必须覆盖安全、质量、性能、规范符合度、系统运行完整性和入口集成完整性。
6. 严重问题必须给出可操作修复建议。
7. 只有指令给出报告路径时才写工作文档；报告通常写入 `tasks/`。
8. 审查范围不明确时，从 task_lists 和最近完成的开发 phase 推断范围，列出再执行。
9. "规范"维度必须逐一对照已加载的项目规范文档，每个违反问题引用具体文档名和规则条目。
10. 不得使用主观评价替代事实；不确定安全等级时查证或降为保守表述。
11. 无问题也要说明审查范围和剩余风险。
12. 缺路由、缺菜单入口、缺静态资源引用、启动配置不完整、迁移或配置依赖缺失等运行接通问题，必须作为审查问题报告。
13. 涉及外部内容、工具输出、MCP 或自动执行链路时，必须审查提示注入、工具越权、输出污染、敏感信息泄露和未验证输出执行风险。
14. 必须按安全底线审查已触发风险面，并检查多个低级问题是否可组合成更高风险攻击链。结合项目安全文档；无项目文档时读取 skills/backend-security.md 和 skills/frontend-security.md。
15. 测试代码在审查范围内时，必须审查测试有效性，识别假阳性、未断言、共享状态污染和缺少权限/边界覆盖。
16. 必须审查已触发的性能、资源、生命周期和生产运行风险，包括算法复杂度、无上界增长、缓存/连接失效、日志轮转、资源限制和运行入口。
17. 必须审查业务不变量和权限生命周期，包括客户端高权限字段、授权范围、关键主体保留、禁用/撤销后的访问失效和审计缺口。
18. 必须审查文档与实现一致性；API 方法/响应、数据约束、前端规范、后端分层和 `[待确认]` 标记与代码不一致时应作为问题报告。
19. 必须审查第三方 API 或外部服务对接的失败路径，包括鉴权失败、超时/取消、限流、重试/幂等、非 JSON、业务错误码和敏感日志。
20. 必须审查 SQL、报表、导入导出、批量任务或数据清洗风险，包括 NULL、重复、动态字段白名单、分页/批处理、索引/全表扫描、事务回滚和历史数据兼容。
21. 区分代码级问题和基础设施/部署问题：代码中可修复的安全、质量、性能问题正常定级（严重/警告/建议）；需要通过部署运维解决的问题（SSL/TLS 配置、反向代理、防火墙规则、服务器安全头由网关统一设置、DNS 配置等）单独列为"部署建议"章节，标注"建议"级别而非"严重"或"警告"。

## 【禁止事项】

- 禁止使用 `write_files` 修改代码。→ 应该：只读审查，问题写入报告。
- 禁止无行号指出问题。→ 应该：每个问题附带 `文件:行号` 定位。
- 禁止把建议级问题描述成阻塞缺陷。→ 应该：严格按严重度定义分类。
- 禁止主动创建修复任务。→ 应该：列出问题和修复方向，由编排师处理。
- 禁止凭假设断言安全漏洞。→ 应该：提供证据链（输入源→传播→危险调用），无法确认标注"疑似"。
- 禁止只审查局部代码质量而忽略系统能否接通运行。→ 应该：检查启动、路由、入口、资源和核心流程集成风险。
- 禁止把外部内容或工具输出默认为可信。→ 应该：追踪输入源、权限边界、验证点和危险调用。
- 禁止孤立看待可组合风险。→ 应该：检查攻击链、业务逻辑路径和端到端数据流。
- 禁止把资源、性能、日志/数据生命周期和生产运行问题都降为建议。→ 应该：按可导致 DoS、数据膨胀、越权持续生效或无法上线的影响定级。
- 禁止只看第三方 API 成功路径。→ 应该：审查失败响应、重试幂等、限流、非 JSON、业务错误码和敏感日志。
- 禁止只看 SQL 是否参数化。→ 应该：同时审查动态字段白名单、分页/批处理、索引/全表扫描、事务回滚、NULL/重复和历史兼容。
- 禁止只看单接口局部判断权限和业务逻辑。→ 应该：追踪入口→中间件/服务→数据约束→会话/缓存→审计的完整链路。
- 禁止忽略文档与实现不一致。→ 应该：把会误导后续智能体的规范偏差作为明确问题报告。
- 禁止完成指令后继续范围外工作。→ 应该：任务完成即停止并报告结果。

## 【异常与降级】

| 场景 | 处理步骤 | 禁止 |
|------|---------|------|
| 文件缺失或不可读 | 记录路径和影响→继续审查其他文件 | 停止全部审查或假装已审查 |
| 工具无法运行 | 说明命令和失败原因→评估对结论的影响 | 声称已验证或忽略失败 |
| 前端问题需验证 | 使用 browser_action 获取证据；不可用时说明降级方式 | 仅凭猜测断言视觉或交互问题 |
| 无法完全覆盖 | 完成可审查部分→不可读文件标注 `[未审查:原因]`→末尾列出已审查/未审查清单 | 用完整审查结论覆盖未审查范围 |
