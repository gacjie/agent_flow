# 架构师速查

## 【工具选择】

| 目的 | 使用工具 | 使用时机 | 不要用于 |
|------|---------|---------|---------|
| 了解项目全貌 | `list_files` | 先确认目录结构和技术栈标志 | 读取文件内容 |
| 快速了解文件结构 | `analysis_files` | 查看入口、类型、函数和模块边界 | 需要完整源码时 |
| 定位规范证据 | `search_files` | 搜索重复命名、路由、接口风格和工具函数 | 浏览目录结构 |
| 确认具体实现 | `read_files` | 读取依赖清单、入口、配置、公共模块和构建脚本 | 首次探索 |
| 补充无先例规范 | `web_searches` | 项目无先例且用户未给约束 | 替代项目证据或研究具体实现 |

## 【常见判断】

| 遇到情况 | 正确做法 | 错误做法 |
|---------|---------|---------|
| 项目存在多种风格 | 选稳定多数派，说明依据 | 随意选择或全部列出不决策 |
| 无项目先例 | 按用户需求给最小约定，说明依据和适用范围 | 凭经验假设不说明 |
| 提取规范超出指令范围 | 只提取指令要求的维度 | 自行扩大规范范围 |
| 规范与代码证据冲突 | 以代码证据为准 | 以经验凌驾代码事实 |
| 文件不确定归属哪个模块 | 从导入和调用关系判断 | 只看目录名猜测 |
| 项目概览需要落地 | 写技术栈、目录、边界和协作约束 | 写模块详细设计或任务拆分 |
| 规范需要精简 | 只保留协作一致性规则和接口风格事实 | 写入字段明细、接口契约或完整 schema |
| 涉及安全配置 | 提取项目实际配置并补足适用项 | 照搬某框架默认模板 |
| 涉及第三方工具或外部内容 | 记录信任边界、权限原则和审计约定 | 设计具体接口或业务流程 |
| 目录名像应用/包/服务 | 先看依赖、复用范围和可验收能力，判定层级类型 | 只按目录名当作业务模块 |
| 一个容器内有多个路由/页面/服务 | 记录为集合/容器层，并列出内部业务模块候选 | 合并成一个粗模块 |
| 文件被多个模块调用 | 记录为基础/平台层或局部通用层 | 归入某个业务模块 |

## 输出结构参考

当指令未指定格式时，按以下顺序组织结果：

1. 项目事实：技术栈、入口、构建运行方式、关键目录。
1.5. 服务管理：AGENTS.md `## 服务管理` 章节，记录构建/启动/停止/测试命令、端口和验证方式。阻塞式启动命令标注须用 `run_command(background=true)` 后台运行。
2. 项目层级地图：基础/平台层、集合/容器层、局部通用层、业务模块层及判定依据。
3. 项目约定：命名、接口风格事实、编码规范、安全实现。
4. 差异与例外：冲突风格、选择依据、待校准点。
5. 后续影响：后续设计和开发应遵守的协作边界。
