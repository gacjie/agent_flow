# Python 后端开发工作流

## 1. 读取任务

用 `task_lists` 确认当前 Python 后端任务。若提供任务 ID，先读取 `task_lists(task_id=..., verbose=true)`，确认 `task_doc`、验收条件和依赖。

## 2. 识别项目范式

扫描项目结构、依赖文件、入口、已有后端模块和测试目录。读取目标文件、同类实现和公共工具，确认框架、错误处理、数据访问和验证方式。任务涉及页面或模板时，还须读取项目基础模板和已有同类页面，确认模板继承结构、可用 block、全局导航和布局模式。

## 3. 实施变更

按任务逐项编码：
- 优先复用现有函数、模型、配置和依赖。
- 保持接口契约、字段名、状态值和错误格式一致。
- 覆盖输入、异常、安全、权限、资源释放等边界。

> 防御示例：外部输入 → Pydantic/Schema 校验；SQL → ORM 参数化查询；文件/连接 → `with` 语句；异常 → 捕获具体类型，不用裸 `except`。
- 修复任务只处理关联问题文档中的问题。

## 4. 验证

按以下层次逐步验证，每层通过后再进入下一层：

1. **语法与导入**：运行语法检查或尝试导入修改的模块，确认无拼写错误、缺失模块或未定义名称。
2. **集成启动**：确认本次修改的模块能被项目入口正确加载——运行项目启动命令或导入入口模块，观察是否报错退出。
3. **接口可达**：若实现了路由或接口，启动服务后至少请求一个端点确认可响应（非 500 错误）。
4. **测试通过**：运行项目已有测试命令。

Python 项目存在 `.venv` 时优先使用。

若验证失败，修复后重跑。无法运行时说明具体原因（缺少外部服务、系统依赖等），不得声称"已验证"而未实际执行命令。

## 5. 收尾

更新任务状态，回复修改文件、验证方式、结果和待确认点。

## 完成检查

- 是否按项目实际识别框架、依赖和测试方式。
- 是否读取目标文件、同类实现和公共工具。
- 是否保持接口契约、字段名、错误格式和权限一致。
- 是否避免裸异常、动态执行和输入拼接风险。
- 是否运行了语法、导入、测试或启动验证。
- 是否更新任务状态并说明无法验证的原因。
- 若任务涉及创建页面或模板，是否确认模板正确继承基础模板、全局布局（header/sidebar/footer/nav）与已有页面一致、引用了项目基础样式和脚本文件。
