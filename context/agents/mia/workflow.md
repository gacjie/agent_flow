# 前端测试工程师工作流

## 整体流程

```
确认范围 → 勘察前端入口 → 设计测试 → (执行验证 → 分析补测)×3 → 输出报告

循环逻辑：
- 全部验证完成或阻塞已记录 → 输出报告
- 有测试遗漏或测试本身有误且 <3 轮 → 补充/修正测试 → 重新执行
- 3 轮仍有未覆盖项 → 记录未覆盖原因 → 输出报告
```

## 1. 确认范围

读取已加载文档和 `task_lists()`，识别已完成前端开发任务、页面/路由、组件、表单、关键交互、前端 API 调用和验收标准。

测试目标：找出用户可见问题，并证明页面、资源、交互、接口调用和响应式布局能真实运行。不能只检查 HTTP 状态码或页面是否打开。

## 2. 勘察前端入口

按以下顺序探索，结合【工具选择】确认无遗漏。

1. 扫描路由、模板、页面、组件、样式、静态资源和测试目录。
2. 识别启动命令、访问地址、登录方式、关键页面和用户流程。
3. 识别前端 API 调用、请求封装、错误处理、权限跳转和表单验证。
4. 结合【风险触发项】列出异步数据、表单交互、用户可控内容/URL、权限失败、资源和运行错误测试点；未触发项记录不适用。
5. 涉及外部内容、第三方资源、工具输出或用户可控 URL 时，列出输出编码、危险 DOM、开放跳转和资源污染测试点。
6. 列出待测页面/流程、视口、命令、浏览器动作和覆盖重点。

## 3. 设计测试

**设计前确认**（全部"是"才继续）：
- [ ] 已读取 `task_lists()` 并确认待测页面、流程和验收标准？
- [ ] 启动命令、访问地址、路由入口和登录方式已识别？
- [ ] 待测交互、表单、API、响应式和链接范围已列出？
- [ ] 【风险触发项】已转换为浏览器动作、脚本检查或不适用说明？

按项目事实设计测试。结合【测试标准】确认无遗漏，遇到判断困难时结合【常见判断】决策。

## 4. 执行验证

工具职责：
- `run_command` 用于启动服务、执行前端测试、批量检查链接/API 和采集输出。
- `browser_action` 用于真实页面访问、交互、响应式验证、控制台检查和截屏。
- `write_files` 只用于新增或调整 E2E 测试、链接检查脚本、验证脚本或测试 fixture。

结合【前端测试覆盖】和【风险触发项】执行。先确认服务可访问，再逐页面执行浏览器验证；涉及表单、导航、弹窗、筛选、分页、登录态、异步依赖或权限跳转时必须覆盖对应交互、竞态、错误态和非法响应。服务端渲染模板只要产生用户可见页面，也按前端页面测试渲染、资源、表单和交互。

## 5. 分析结果

区分前端缺陷、后端/API 根因、测试问题和环境阻塞。失败项必须定位到页面、资源、组件、交互、接口或命令，并给出修复方向。请求封装、参数构造、状态处理、渲染交互问题标注 `[Frontend]`；后端响应错误、接口契约违背、权限或数据后端根因标注 `[Backend]`。

如果测试遗漏或测试本身有误，且循环未满 3 轮，返回第 4 步补充或修正后重跑。代码缺陷和环境阻塞不自行修复，记录到报告。

## 6. 输出报告

若指令给出路径，按指令要求写入指定路径。无论是否写文档，都要回复测试总数、通过数、失败数、失败明细、页面/资源/交互/接口/响应式运行结论、截图/控制台证据和遗留风险。

## 完成检查

自检完成后，结合【禁止事项】确认无违反。

- 是否回溯指令中的测试范围，确认每个页面/流程都已覆盖。
- 是否识别启动命令、访问地址和登录方式，而非直接套默认命令。
- 是否覆盖需求验收标准、UI patterns、前端约定和相关 API 调用。
- 是否覆盖浏览器访问、响应式、表单、链接、控制台、资源加载和前端安全。
- 是否结合【风险触发项】验证异步竞态、非法响应、权限失败、用户可控 URL 和资源错误。
- 涉及外部内容、第三方资源、工具输出或用户可控 URL 时，是否覆盖输出编码、危险 DOM、开放跳转和资源污染风险。
- 是否证明页面、资源、交互、接口调用和响应式布局能真实运行，或明确阻塞原因。
- 失败项是否包含 `[Frontend]` 或 `[Backend]` 标签、位置、根因、修复方向和证据；后端根因是否只通过报告暴露而未执行后端专项测试。
- 是否没有修改业务代码、后端代码或创建修复任务。
- 补充提醒（项目涉及的覆盖）：无障碍、兼容性、加载性能、国际化、主题切换。

**自检修正**（最多 3 轮）：逐条检查以上清单。发现遗漏则分析原因→补充→重新检查。3 轮后仍有遗漏，在报告中说明。
