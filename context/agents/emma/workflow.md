# 前端开发工作流

## 1. 读取任务

使用 `task_lists` 确认当前前端任务。若给出任务 ID，先读取 `task_lists(task_id=..., verbose=true)`，确认关联文档、验收条件和依赖接口。

## 2. 识别前端体系

读取项目模板布局、主样式、主脚本和同类页面。记录模板继承、CSS 变量、组件类、主题机制、请求封装、CSRF/认证获取方式。

> 识别示例：读取 `layout/admin.html`（主模板）→ 找到 `css/app.css`（CSS 变量定义）→ 读取 `js/app.js`（公共交互）→ 读取同类页面如 `admin/member_list.html` → 记录：布局用 `{{define "admin_content"}}`，颜色用 `var(--color-primary)`，请求用 fetch + CSRF header。

## 3. 实施变更

按任务完成结构、样式、交互：
- 模板遵循项目布局和语义结构。
- 样式复用变量和组件，不破坏主题。
- 脚本使用安全 DOM API、事件绑定和项目请求封装。
- 修复任务只处理问题文档覆盖的前端问题。

## 4. 验证

使用项目测试方式或 `browser_action` 验证：
- 页面可访问且静态资源正常加载（无 404、页面有样式渲染效果）。
- 关键元素存在、交互正常、控制台无相关错误。

需要时补充网络或 DOM 证据。

## 5. 收尾

更新任务状态，回复修改文件、验证页面、验证结果和遗留风险。

## 完成检查

- 是否读过主模板、主 CSS、主 JS 或同类页面。
- 是否遵循 API 契约和字段映射。
- 是否处理加载、成功、失败、空数据和权限失败场景。

> 状态处理模式：加载中 → spinner 或骨架屏；成功 → 渲染数据；请求失败 → toast 提示 + 重试按钮；空数据 → "暂无数据"占位；403 → 跳转登录或无权限提示。
- 是否避免不可信 HTML、内联事件和全局污染。
- 是否适配项目已有主题和响应式规则。
- 是否完成浏览器或项目测试验证并更新任务状态。
- 新增或修改的页面是否正确引用了所需的 CSS/JS 文件；新增的 CSS/JS 文件是否被对应模板引用。
